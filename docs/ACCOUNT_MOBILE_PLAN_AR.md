# مخطط وتنفيذ فضاء المستخدم — الهاتف أولًا

## الهدف والنطاق
تطبيق مرجع المستخدم داخل AYROVI: بطاقة هوية خفيفة، قوائم مجمعة، وخروج واضح، مع لمسات وزر رئيسي بالبرتقالي يربطانه بصريًا بتسجيل الدخول. لا بيانات تجريبية في واجهة الإنتاج، ولا أزرار بلا وجهة، ولا تغيير لإعدادات Google أو Resend. الحساب وشاشاته الفرعية هي نطاق العمل؛ بقية المتجر لا يعاد تصميمها.

## خريطة المعلومات
- **بطاقة الحريف:** صورة الحساب الحقيقية أو أول حرف من الاسم، الاسم، البريد/الهاتف، تعديل الملف.
- **اختصاران:** المفضلة والسلة، بعدادات حقيقية حين تتوفر البيانات.
- **عام:** الطلبات، العناوين، الإشعارات، الدخول والأمان، التفضيلات.
- **الطلبات:** شريط داخلي للطلبات والتتبع والمدفوعات والفواتير، يحافظ على كل الوظائف دون ازدحام الواجهة الرئيسية.
- **المساعدة:** إرشادات Lens مع فتح العدسة/المساعد الحقيقي، ثم الشروط والخصوصية.
- **الخروج:** زر واحد واضح، ينتظر تأكيد الخادم ولا يخفي أخطاء فشل الخروج.

لا يُنسخ «QR» أو «Pickup location» من المرجع لعدم وجود وظيفة مقابلة مطلوبة هنا. المواقع والتوصيل تمر عبر عناوين الحساب الفعلية، لا خانة موقع محفوظة محليًا.

## الربط الفعلي
| الوظيفة | المصدر / العقد |
|---|---|
| الاسم والبريد | جلسة العميل + PUT account/profile |
| الصورة | POST / DELETE account/avatar، معالجة صورة آمنة وحفظ دائم في الحساب |
| العدادات | GET account/overview؛ فشل التحميل لا يُعرض كأصفار وهمية |
| الطلبات والتفاصيل | GET account/orders والطلب المحدد مع عزل ملكية العميل |
| المدفوعات والفواتير والتتبع | مسارات الحساب الحالية، دون إنشاء مدفوعات أو فواتير مصطنعة |
| العناوين | CRUD account/addresses مع العنوان الافتراضي |
| المفضلة | قائمة وحذف من account/favorites؛ لا رابط # إذا غاب مصدر المنتج |
| السلة | واجهة cart الحالية وتحديث الكميات الفعلية |
| الإشعارات | قراءة ثم تحديث عداد غير المقروء من البيانات المحفوظة |
| كلمة المرور | تغيير مصادق عليه بكلمة المرور الحالية؛ إبطال الجلسات/الروابط القديمة وتدوير الجلسة الحالية |
| حساب OAuth بلا كلمة مرور | إظهار مزوّدات الحساب الفعلية، لا نموذج كلمة مرور غير قابل للعمل |
| الوضع الداكن والتنبيهات | GET/PUT account/preferences مع حفظ الإعدادات واستعادتها عند الدخول |
| المساعدة والقانونيات | وجهات حقيقية داخل التطبيق أو صفحات HTML الموجودة |

## قواعد الدمج
1. استخدام توكنز الألوان والخطوط والمسافات الموجودة؛ لا مكتبة واجهة بديلة.
2. أهداف لمس 44–52px، حقول 16px على الهاتف، اتجاه عربي RTL، ومناطق شاشة آمنة.
3. استبدال القائمة الطويلة المكررة، لا وضع واجهة جديدة فوقها مع إبقائها مخفية.
4. منع تسرب بيانات حساب سابق: إعادة تركيب مكوّن الحساب عند تغير المعرّف، تجاهل الطلبات القديمة، وتنظيف حالات التحميل.
5. شريط عنوان ثابت، ومسار رجوع صحيح مع إعادة التمرير لبداية القسم الجديد.
6. إشعار نجاح الدخول مختصر ومؤقت؛ الأخطاء تبقى واضحة وقابلة لإعادة المحاولة.
7. حالات تحميل/فارغ/خطأ مستقلة. زر رجوع أو بحث/تسوق حيث يناسب الحالة الفارغة.
8. إزالة حفظ الصور والجنس والموقع محليًا كبديل للحساب. لا استنتاج جنس العميل من اسمه.
9. رفع الصورة مع حدود حجم ونوع وفك ترميز وإعادة ترميز، لا ملفات SVG أو صور غير صالحة.
10. لا نشر تلقائي قبل عرض النتيجة للمراجعة لهذه الشاشة الجديدة.

## مراحل التسليم
- فحص الأقسام والعقود الفعلية وتوثيق الخريطة.
- إكمال الربط الناقص في الخادم (الصورة والأمان) وإصلاح حفظ التفضيلات الجزئي.
- بناء مكونات حساب قابلة للصيانة ونقل الواجهة الحالية إليها.
- اختبار عزل الحساب، الملفات، تغيير كلمة المرور، الخروج، الحفظ، والرجوع.
- اختبار الهاتف والفرنسية والعربية والوضع الداكن والأخطاء.
- تقديم صور من التطبيق الفعلي ونتائج الاختبارات، ثم انتظار الموافقة قبل النشر.
