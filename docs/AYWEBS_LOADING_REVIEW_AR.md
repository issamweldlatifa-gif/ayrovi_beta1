# مراجعة تعليق زر AYWEBS في التحميل

## ما تؤكده الصور وما لا تؤكده

تظهر الصورة زر التحميل ومرحلة «Lecture de la page». السجلات المرفقة هي نجاح `page_analyze`، أي تصنيف الرابط؛ لا تثبت اكتمال طلب `product/resolve` أو عرض ورقة الاختيار على الجهاز. لم يُجر اتصال بلوحة Render أو اختبار هاتف فعلي.

## أسباب التعليق الموجودة في الكود

- `requestCapture` كان ينتظر رسالة WebView دون مهلة، ولم يكن يستخدم مرجع المؤقت المعرّف في الشاشة.
- `prefetchReading` كان يعطّل Add ويعرض تحميلًا أثناء القراءة الاستباقية؛ فقدان رسالة الجسر يجعل الزر غير قابل لإعادة المحاولة.
- لم تكن طلبات الجسر مرتبطة بمعرّف قراءة، ولم يكن تغيير الصفحة يلغي القراءات السابقة وينظف نتائجها.
- `onMessage` كان يوقف حالة busy عند وصول الرسالة قبل انتهاء حل المنتج، بدل امتلاك عملية Add لحالة التحميل إلى نهايتها.
- مهلة عميل HTTP كانت تنتهي عند وصول ترويسات الرد، قبل اكتمال قراءة جسم الرد.

## التعديلات

- القراءة الاستباقية لا تعطّل زر Add ولا تعرض تحميلًا على الزر.
- ضغط Add يضبط busy من البداية وينهيها في finally، والورقة لا تفتح إلا بعد قرار صالح من الخادم.
- حد قراءة الجسر 15 ثانية شامل جلب السكربت وانتظار الصفحة والمحاولات؛ حد العملية الكلية 15 ثانية إضافة إلى ميزانية حل المنتج الحالية.
- حد مستقل لقراءة الخلفية والتحقق منها، مع إلغاء موارد القراءة عند انتهاء المهلة أو الخروج.
- كل قراءة لها معرّف؛ الرسائل المتأخرة أو غير المرتبطة لا تحسم طلبًا أحدث.
- تغيير رابط الصفحة يلغي العملية القديمة ويمسح الورقة والنتائج والمراجع المرتبطة بها.
- تنظيف إعادة المحاولات والمستمعين عند الإلغاء؛ القراءة الاستباقية الجارية لا تُعاد مشاركتها إلى أجل غير محدود.
- إلغاء التحليل السابق عند تغيير الصفحة، وإبقاء مهلة HTTP فعالة خلال قراءة جسم الرد أيضًا.

لم تتغير قواعد التقاط السعر أو تسعيره أو التحقق منه في الخادم.

## التحقق

من `apps/mobile`:

```sh
npm run typecheck
npm test -- --run
npm run test:ui -- --runInBand --detectOpenHandles tests/ui/storeBrowserLoading.ui.test.tsx
```

اختبارات المنطق: 766 ناجحة. اختبارات واجهة دورة التحميل الجديدة: 4 ناجحة، تشمل النجاح وفتح الورقة، فقدان رد الجسر وإعادة المحاولة، تجاهل الرد القديم بعد التنقل، وحد انتظار رد الخادم. الاختبارات تستخدم WebView وطلبات محاكية، وليست تجربة حية على Amazon أو Zalando.

## النشر والتجربة

الإصلاح داخل تطبيق Expo/React Native. يلزم بناء وتثبيت APK محدث أو قناة تحديث تطبيق مهيأة بالفعل؛ نشر Render وحده لا يحدّث JavaScript التطبيق المثبت. لم يتم بناء APK أو رفع هذه التعديلات إلى GitHub ضمن هذه المراجعة.

بعد التثبيت: افتح منتجًا، اضغط Add، وتحقق من ظهور الورقة بعد حل المنتج. عند تعذر القراءة يجب أن يتوقف الدوران مع رسالة وإمكانية إعادة المحاولة. جرّب أيضًا تغيير الرابط أثناء التحميل، وإغلاق الشاشة وإعادة فتحها، وانقطاع الشبكة.
