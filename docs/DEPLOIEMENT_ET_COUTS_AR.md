# النشر والتكاليف — هل يجب الدفع حتى يعمل التطبيق؟

> بتاريخ 2026-10-04 · جواب مباشر على سؤال المالك: «هل التطبيق لن يعمل إلا إذا
> دفعنا تحديثاً إلى Render؟»

## الجواب القصير: لا

ثلاث حقائق تصحّح اللبس:

1. **التحديث (النشر) مجاني على Render.** لا توجد «رسوم تحديث» إطلاقاً. الدفع في
   Render يكون مقابل *الاستضافة الشهرية* للخطة، لا مقابل عدد النشرات. صفحة
   الأسعار الرسمية تضع «Deploy for free» في كل الخطط، بما فيها المجانية.
2. **خطة مشروعك مدفوعة أصلاً — التحديث لا يضيف درهماً.**
   `render.yaml` في المستودع يعلن: `plan: starter` (‏7$/شهر) + قرص دائم 1 غيغا
   (‏0.25$/شهر) ≈ **7.25$/شهر**، تُدفع سواء نشرتَ الإصلاح أو تركتَ الخادم كما هو.
3. **التطبيق يعمل — العلة واحدة ومحصورة.** الـ APK يُثبَّت، يفتح، يتصل، يعرض
   المتاجر والمنتجات… المشكلة الوحيدة أن الخادم القديم يقرأ سعر أمازون **0**،
   فيمنع الإضافة للسلة (وهذا سلوك سليم: لا سعر ⇒ لا سلة). إذن الحديث ليس عن
   «تشغيل التطبيق» بل عن «إظهار سعر أمازون».

## خياراتك الأربعة بالتكلفة الحقيقية

| الخيار | التكلفة | الزمن | الملاحظة |
|---|---:|---|---|
| **أ) دفع الإصلاح إلى Render (موصى به)** | **0$ إضافي** | ~4 دقائق | أنت تدفع الاستضافة أصلاً. `git push` → Render يبني وينشر تلقائياً |
| **ب) تجربة فورية بلا Render** | **0$** | ~10 دقائق | تشغّل الخادم المصحّح على حاسوبك + نفق Cloudflare مجاني، وتبني APK موجّهاً إليه |
| **ج) نقل الاستضافة** | 4–7$/شهر | ساعة | Hetzner ≈4€، Oracle Always Free = 0$ (ARM)، Fly/Koyeb… مع قرص دائم |
| **د) Render المجاني** | 0$ | — | **لا يُنصح**: بلا قرص دائم ⇒ تُمسح قاعدة SQLite والصور عند كل نشر/إعادة تشغيل، و«نوم» بعد 15 دقيقة خمول مع إيقاظ بطيء ~دقيقة |

> ملاحظة على الخيار (أ): إن كانت خدمتك الحالية على الطبقة المجانية لا على
> `starter`، فالنشر يبقى مجانياً، لكن كن على علم بمشكلة القرص/النوم أعلاه —
> وهي قائمة قبل الإصلاح وبعده.

## ما أضفته الآن لتسهيل الخيار (ب) والاختبار على أي خادم

كان عنوان الـ API **محفوراً** في `client/src/services/apiOrigin.ts`، أي أنه
مخبوز داخل الـ APK. صار قابلاً للتحديد عند البناء:

```bash
# بناء موجَّه إلى خادمك المحلي (عبر نفق) — بلا تعديل أي ملف
VITE_AYROVI_API_ORIGIN=https://xxxxx.trycloudflare.com npx vite build
npx cap sync android && cd android && sh ./gradlew assembleDebug
```

وبدون هذا المتغيّر يعود السلوك إلى `https://ayrovi-beta1.onrender.com`
بالضبط كما كان (لا انحدار). مُتحقَّق منه: بنيت النسختين وفحصت الحزمة الناتجة.

### تفصيل الخيار (ب) خطوة بخطوة (على حاسوبك، لا هنا)

```bash
# 1) على الحاسوب — تشغيل الخادم المصحّح
npm ci && npm run build
cp .env.example .env         # ثم اضبط ADMIN_* و CUSTOMER_AUTH_SECRET
DATABASE_PATH=./data/local.sqlite node dist/server.js     # يستمع على :3000

# 2) على الحاسوب — نفق مجاني بلا حساب (يطبع عنوان https مؤقتاً)
cloudflared tunnel --url http://localhost:3000
#   → https://quelque-chose.trycloudflare.com

# 3) بناء APK موجَّه إلى ذلك العنوان
VITE_AYROVI_API_ORIGIN=https://quelque-chose.trycloudflare.com npx vite build
npx cap sync android && (cd android && sh ./gradlew assembleDebug)
```

حدود هذا الخيار بصراحة: العنوان يتغيّر في كل تشغيل للنفق، والحاسوب يجب أن يبقى
مشتغلاً — فهو للتجربة لا للإنتاج.

## تذكير: ما لم يُنشر بعد

الإصلاح كله (قارئ أمازون + الصفحة القادمة من الـ WebView) موجود في المستودع
عندك وفي `deliver/aywebs-amazon-price-fix.patch`. حتى يُنشر على الخادم، يظل
التطبيق يرسل الصفحة ويهملها الخادم القديم بصمت — بلا أي تراجع، لكن بلا سعر.
