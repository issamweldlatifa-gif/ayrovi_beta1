# التقرير النهائي لإصلاح AYROVI

**التاريخ:** 16 أغسطس 2026  
**النسخة بعد الإصلاح:** `3.4.1`
**نقطة البداية:** `a2a9b023b1b131c475616c6f6db808b3d8ab9c53`  
**الحالة:** الإصلاحات البرمجية الحرجة وتحديث Social/الهوية/AYROVIX والمساعد ووكيل «مجلتي» داخل Admin مكتملة في النسخة `3.4.1`؛ التحقق المحلي كامل، والتحقق الإنتاجي موثق أدناه.

> **الحالة الإنتاجية المؤكدة في 16 أغسطس 2026:** نُقلت قاعدة الإصلاح من `3.2.1` إلى `3.3.0` مع سجل تنقل داخلي شامل لزر Back وتحديث Social والهوية وAYROVIX والمساعد، ثم نُشرت النسخة `3.4.0` التي تضيف وكيل «مجلتي» المحرري داخل Admin فقط، وأتبعتها `3.4.1` لإصلاح قراءة جواب Claude متعدد الكتل مع مسار إصلاح تلقائي. تسجيل Google وAI وVisual Search والصوت جاهزة. أضيف Facebook OAuth كاملًا لكنه يبقى معطّلًا آمنًا إلى أن ينشئ المالك تطبيق Meta ويضبط أسراره. البريد وOTP SMS ما زالا غير مفعّلين. ### وكيل «مجلتي» داخل Admin — النسخة `3.4.0`

نُفذت الملفات الثلاثة المرفقة: أمر التنفيذ، System Prompt، وكراسة المواصفات التقنية، مع إبقاء الوكيل خاصًا بالمحررين داخل لوحة الإدارة:

- تغيّر اسم العرض **Actualités** إلى **مجلتي** في الواجهة العامة وAdmin من دون تغيير route أو البيانات؛ بقي المسار الداخلي `news` كما هو.
- أضيف تبويب مستقل **وكيل مجلتي** بجانب Social/مجلتي، بواجهة محادثة عربية RTL وبطاقات نتائج، ولا يُحمّل ضمن واجهة الزائر.
- رُبط الوكيل بخادم Anthropic الرسمي عبر `/v1/messages` مع System Prompt التحريري، وClaude Web Search، ومخرج JSON منظم مع fallback دفاعي إذا رفض المزود الجمع بين Structured Outputs وWeb Search.
- التوليد بالجملة يدعم حتى 10 أفكار، يعرض Progress حقيقيًا، ويولّد النتائج تباعًا. كل فكرة تنتج أربع بطاقات: Editorial وPublication وStory وReel، بدل إغراق المحادثة بردود طويلة.
- أُنشئ جدول SQLite دائم `magazine_drafts`؛ كل بطاقة تُحفظ تلقائيًا بحالة `draft` مع conversation/batch/model والمراجع والوسائط والمنتج، ويمكن الرجوع إليها بعد إغلاق المحادثة.
- بحث المنتج Read-only: لا يقبل الوكيل `product_id` خارج قاعدة AYROVI، ويعيد الاسم والصورة والرابط والسعر من السجل الحقيقي فقط. التطابق الغامض أو المنتج غير الموجود يعيد طلب توضيح وقائمة مقترحات بدل اختراع بيانات.
- أضيف Drag & Drop من بطاقة الوكيل إلى تبويب «مجلتي» في Sidebar وإلى Drop Zone داخل صفحة المجلة، مع Modal تأكيد للتصنيف والحفظ كمسودة أو الجدولة.
- الجدولة فعلية عبر حالة نشر مع تاريخ مستقبلي؛ Public APIs لا تعرض المحتوى قبل الموعد. لا تُجدول بطاقة Social بلا صورة مملوكة، ولا Reel/Story بلا فيديو Pexels/Pixabay مرخص أو وسيط منتج حقيقي.
- الصور المرجعية تأتي من Google Images عبر SerpApi وتُخزن بعلامة **مرجعي فقط** ولا تنتقل تلقائيًا إلى حقول النشر.
- الفيديو يأتي من Pexels/Pixabay API عند وجود المفاتيح، مع fallback إلى Claude Web Search محصور في صفحات المكتبتين؛ رابط البحث/المكتبة لا يوسم «مرخص للنشر» قبل اختيار ملف حقيقي.
- ربطت البطاقة المؤكدة بأنظمة CMS الحالية: المقالة إلى `news_items`، والمنشور إلى `publications`، والريل إلى `reels`، والستوري إلى `stories`، مع إبقاء الحالة غير عامة حتى قرار المحرر أو موعد الجدولة.
- الحماية: صلاحيات `content:read/write`، جلسة Admin وCSRF، rate limit، منع توليدين متزامنين للمحرر نفسه، حدود طول/Batch، فلترة الروابط العامة ورفض hosts الخاصة، وAudit logs للتوليد والحفظ والنقل والحذف. إعادة البطاقة إلى Draft تلغي جدولة CMS أيضًا، وحذف بطاقة منقولة يؤرشف هدفها كي لا تُنشر لاحقًا بالخطأ.
- أضيفت متغيرات `MAGAZINE_AGENT_MODEL`, `PEXELS_API_KEY`, `PIXABAY_API_KEY` إلى أمثلة التشغيل وRender؛ مفاتيح Stock اختيارية لأن Web Search يعطي fallback فعليًا، بينما API المباشر مطلوب لجلب ملف فيديو جاهز للجدولة.

اختبارات وكيل مجلتي تغطي: الأعداد العربية والحد 10، سياسة المنتج الحقيقي والغموض، الحفظ التلقائي لأربعة أنواع، النقل الآمن إلى CMS، منع نشر الصورة المرجعية، الجدولة المستقبلية، منع Social بلا Media مرخصة، واستدعاء Anthropic Web Search. الإجمالي المحلي أصبح **126/126** في 12 ملفًا، مع TypeScript وBuild ناجحين.

### إصلاح بنية جواب Claude — النسخة `3.4.1`

كشف أول توليد إنتاجي حقيقي أن Anthropic أعاد جوابًا ناجحًا لكن Web Search وزّعه على أكثر من كتلة نصية أو أحاط JSON بنص تمهيدي؛ كان المحلل القديم يدمج الكتل ثم ينفذ `JSON.parse` واحدًا، فظهرت رسالة «تعذر قراءة بنية المحتوى المولّد». لم يكن ذلك خطأ مفتاح: `/api/ready` ظل يؤكد `magazineAgent=true` ووصل التنفيذ أصلًا إلى مرحلة تحليل جواب المزود.

نُفذ الإصلاح الدفاعي التالي:

- تحليل كتل `text` كل واحدة على حدة بدءًا من الأخيرة، ثم النص المجمّع.
- إزالة Markdown fences وقبول JSON الذي تسبقه مقدمة نصية.
- استخراج كائنات JSON المتوازنة مع مراعاة علامات الاقتباس والـescape بدل قص أول `{` وآخر `}` بشكل غير آمن.
- التحقق من البنية وتطبيعها قبل الحفظ؛ لا تُحفظ أي مسودة جزئية عند الفشل.
- عند استمرار الفشل أو غياب كتلة نص مكتملة، تُنفذ جولة Anthropic ثانية بلا Web Search وبـJSON Schema صارم لإصلاح الرد الخام أو إعادة بنائه من سياق أمر المحرر.
- الاحتفاظ بمراجع Web Search من الجولة الأصلية بعد الإصلاح، مع تسجيل تشخيص آمن لنوع الكتل و`stop_reason` بلا مفاتيح أو بيانات سرية.

أضيف اختبار لجواب متعدد الكتل مع مقدمة وJSON داخل Markdown، واختبار لمسار الإصلاح الخادمي قبل الحفظ. أصبحت النتيجة **127/127** اختبارًا ناجحًا في 12 ملفًا، مع نجاح TypeScript وBuild و`npm audit` بصفر ثغرات و`git diff --check`.

نُشر Commit `e3f7537` على الفرعين، وأكد `/api/health` انتقال Render فعليًا إلى **3.4.1**. أكد Smoke الإنتاجي أن قاعدة البيانات جاهزة وأن `magazineAgent`, `magazineImageSearch`, `magazineStockVideo` مفعلة، وأن تبويبات «مجلتي» و«وكيل مجلتي» و«مسودات الوكيل» وعقد Drag & Drop ما زالت في Bundle الجديد، وأن Admin API يعيد 401 بلا جلسة. يبقى تأكيد النتيجة النهائية للتوليد المدفوع عبر إعادة المحرر للأمر داخل جلسة Admin؛ لا يمكن لفحص عام غير مصادق إنشاء مسودة إنتاجية بدلًا عنه.

## 3) ما ينقصنا قبل الإطلاق الإنتاجي

### حالة التكاملات

#### 1. متغيرات الخدمات الخارجية — ✅ Google وAI فعّالة؛ ⚠️ Facebook والبريد وSMS متبقية

فحص خدمة `ayrovi-beta1-1` بعد نشر 3.2.1 يثبت أن Google وAI وVisual Search والصوت فعالة. Facebook مدمج ويظهر `facebookLogin=false` حتى إنشاء تطبيق Meta وضبط `FACEBOOK_*`. يبقى `mail=false` حتى شراء نطاق وتوثيقه وضبط `MAIL_*`، و`sms=false` حتى اختيار مزود تونسي وربط API/Webhook.

#### 2. CARD — ✅ تدفق يدوي مقصود

أكد المالك أن CARD يعمل كتدفق تحصيل يدوي آمن ثم مراجعة/تأكيد من Admin. لا تُعد بوابة الدفع Online شرطًا ما دام هذا هو نموذج التشغيل المعتمد، والنص الحالي يوضح أن الفاتورة والتتبع يأتيان بعد تأكيد التحصيل ولا يطلب إرسال بيانات البطاقة في الرسائل.

يمكن إضافة بوابة Online لاحقًا كتطوير اختياري، مع Webhook موقّع وIdempotency، وليست عائقًا حاليًا أمام Pilot اليدوي.

### P0 المتبقي لاعتماد إطلاق عام واسع

#### 3. إكمال Environment Variables في خدمة Render

تأكدت صلاحية إعدادات Google وAI وVisual Search والصوت في خدمة `ayrovi-beta1-1`. يجب الحفاظ على `PUBLIC_BASE_URL` وGoogle callback للرابط الجديد. المتبقي هو:

- إنشاء تطبيق Meta ثم ضبط `FACEBOOK_APP_ID`, `FACEBOOK_APP_SECRET`, `FACEBOOK_CALLBACK_URL`.
- ضبط `MAIL_PROVIDER`, `MAIL_API_KEY`, `MAIL_FROM` بعد شراء نطاق وتوثيقه.
- ضبط Webhook مزود OTP التونسي بعد اختياره.
- اختياريًا: ضبط `PEXELS_API_KEY` أو `PIXABAY_API_KEY` لجلب ملف فيديو Stock مباشر جاهز للجدولة؛ من دونهما يبقى البحث الحقيقي داخل المكتبتين عبر Anthropic Web Search ويحتاج المحرر اختيار/رفع المقطع.
- ضبط `BACKUP_S3_*` وتغيير `BACKUP_REQUIRE_EXTERNAL=true` بعد نجاح أول رفع.

لا تُرسل أي أسرار في المحادثة أو GitHub.

#### 4. تفعيل مزود OTP تونسي بدل Twilio

Twilio غير معتمد تشغيليًا لأن المالك أوضح أنه لا يلائم احتياجه في تونس. يجب طلب تجربة وعرض من Orange Tunisie Messaging Pro وTunisieSMS، والتحقق من وصول OTP إلى Orange وOoredoo وTunisie Telecom ومن دعم Sender ID وتقارير التسليم. بعد اختيار المزود يمكن استخدام `CUSTOMER_OTP_PROVIDER=webhook` أو إضافة Adapter مباشر في `src/customer/otp.ts`. بعدها يجب أن تصبح `phoneOtp.enabled=true` وتُختبر رسالة حقيقية إلى رقم يحدده المالك خارج المحادثة العامة.

#### 5. الصفحات القانونية — ⚠️ الأساس التقني منشور والمراجعة القانونية متبقية

نُشرت سياسة خصوصية تقنية وصفحة حذف البيانات، وربطتا بالـFooter، كما أصبح حذف الحساب ذاتيًا من الملف الشخصي. المتبقي الذي يحتاج بيانات المالك ومراجعة قانونية فعلية:

- الشروط العامة للبيع/الوساطة وسياسة الإلغاء والإرجاع والاسترجاع.
- الاسم القانوني للشركة، المعرف الجبائي/السجل عند الاقتضاء، العنوان ووسائل الاتصال.
- تشغيل `contact@ayrovi.tn` فعليًا.
- تثبيت مدد الاحتفاظ القانونية بالمرفقات وإثباتات الدفع والفواتير والمحادثات.
- سياسة Cookies إذا أضيفت أدوات تحليل أو تسويق.

لا يصح اختلاق هذه البيانات برمجيًا؛ الصفحتان المنشورتان تحتاجان اعتمادًا قانونيًا قبل الإطلاق العام.

#### 6. Backup خارجي آلي — ⚠️ الكود والجدولة جاهزان، الاعتماد الخارجي متبقٍ

أصبح السكربت يدعم S3/R2/B2 بتوقيع server-side، وأضيف Scheduler يومي قابل للضبط داخل خدمة Render. نجح اختبار النسخة المحلية وفحص `quick_check=ok`. المتبقي تشغيليًا:

- إنشاء Bucket خارجي وضبط `BACKUP_S3_*`.
- نجاح أول Upload ثم تفعيل `BACKUP_REQUIRE_EXTERNAL=true`.
- وضع Lifecycle/Retention خارجي.
- اختبار Restore شهري موثق.
- ربط فشل النسخ بتنبيه خارجي.

#### 7. تحقق مستقل من رحلة الإنتاج

أكد المالك أن دورة الطلب والعربون والبريد والفاتورة كاملة. بعد تفعيل البريد ومزود OTP التونسي، يجب تنفيذ رحلة Smoke حقيقية على رابط Render الجديد وتوثيق النتيجة:

```text
تسجيل Google وFacebook وOTP
→ صورة Lens ورابط وQR
→ تأكيد سعر متجر
→ سلة
→ Checkout
→ دفع/عربون
→ رفع إثبات
→ مراجعة Admin
→ إرسال بريد
→ فاتورة
→ تتبع
```
