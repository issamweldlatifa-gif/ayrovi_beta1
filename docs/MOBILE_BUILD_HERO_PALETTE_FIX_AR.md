# إصلاح توقف بناء APK عند اختبار الألوان

- التشغيل الفاشل: 42556617233، commit 1810bf9e، في خطوة npm test قبل إنشاء APK.
- الصورة أظهرت brand-colors.test.ts؛ أعيد إنتاج الخطأ محليًا: اللون #A37549 مرتين في tokens.mobile.ts. كان متوسط لون صورة الطفل، وليس لون زر أو حالة. الفحوصات الجزئية في التسليم السابق لم تشمل brand-colors؛ لذلك لم تكتشف المشكلة.
- نُقلت ألوان حواف الصور إلى assets/hero/palette.json كبيانات محتوى، مع استمرار تصدير HERO_DEMO_EDGES بنفس الاسم. لم يُعطّل أي اختبار أو يوسّع whitelist أو تتغير ألوان الهوية.
- صُحّح حساب الحواف أيضًا: sharp.stats() لا يطبّق extract المعلّق، فكانت القيم السابقة متوسط الصورة كاملة. القيم الجديدة متوسط الصف الأعلى والأسفل بعد materialize إلى raw buffer، دون تغيير الصور نفسها.
- أضيفت 8 اختبارات لعقد بيانات الصور، وصلاحية الألوان، وفصل المصدر عن ألوان الواجهة، واختلاف العينات بدل المتوسط الواحد. لا تعتمد على sharp في CI ولا على تثبيت حزم الجذر؛ لم تضف تبعيات.

التحقق المحلي بعد الإصلاح:
- جميع اختبارات الموبايل: 120 ملف / 1170 اختبار ناجح.
- جميع اختبارات الواجهة: 55 مجموعة / 336 اختبار ناجح (الحاضنة الحالية مع --forceExit وتحذيرات act).
- TypeScript وtokens:check ناجحان.
- النجاح المحلي ليس إثبات نجاح Gradle أو جاهزية APK؛ يُتابع تشغيل GitHub بعد الرفع.
