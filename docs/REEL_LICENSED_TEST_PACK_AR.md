# حزمة خمسة فيديوات مرخّصة لاختبار Reels

> تحديث لاحق: طلب المالك استبدال كل فيديوات Reels السابقة بخمسة ملفاته من Drive. حزمة الأمثلة والأداة اليدوية المذكورة تاريخيًا هنا أزيلتا؛ المرجع الحالي [فيديوات المالك](REEL_OWNER_COLLECTION_AR.md). لا تُعد إضافة عينات CC0 القديمة.

## تحديث: نشر تلقائي وافق عليه المالك

بعد موافقة المالك على النشر ثم طلبه إضافتها مثل الصور، أصبحت الخمسة تُدرج تلقائيًا عند أول تشغيل backend يحتوي هذا التحديث. لا يلزم Shell أو متغير بيئة أو APK جديد لإضافة الصفوف. يلزم **نشر كود الخادم والأصول فعلًا**؛ رفع الفرع وحده ليس إثبات نشر Render.

`src/magazine/installReelTestPack.ts` يتحقق من الأصول والتعارضات، ثم constructor ينشئ snapshot ملفية مفحوصة قبل الإدراج، ثم يُدرج الصفوف وعلامة `licensed_reel_test_pack_v1` في معاملة واحدة. لا snapshot للقاعدة :memory: المستعملة في الاختبارات. لا UPDATE/DELETE لصف قديم. إذا كانت الإضافة اليدوية تمت سابقًا بنفس المعرفات/الفيديوات تُحفظ الصفوف كما هي. تعارض معرف مع فيديو آخر أو أصل مفقود أو فشل backup يمنع الدفعة ولا يكتب العلامة؛ يُسجل خطأ ثابت دون SQL/بيانات حساب، ويبقى المتجر يعمل وتُعاد محاولة هذه الدفعة عند إقلاع لاحق.

بعد كتابة العلامة، تعديلات المالك والإخفاء والحذف تبقى محفوظة؛ إعادة الإقلاع لا تعيد الفيديو المحذوف ولا تنشئ backup جديدة لهذه الدفعة. لا تغيير schema أو إعدادات استضافة/تخزين أو واجهة الويب. الـbackup عند بداية هذه الدفعة فقط، لا ضمان rollback لكل ما فعله bootstrap قبلها.

التحقق بعد هذا الربط: 11 ملفًا / 47 اختبارًا ناجحًا، يشمل startup/reopen ونسخ/استرجاع وعلاقات وقراءات وكتابات اجتماعية. TypeScript والبناء الكامل نجحا. جرى الإدراج على قواعد اختبار فقط ضمن الجلسة؛ لم يُثبت وصول deploy إلى الخدمة الحالية. الأقسام التالية توثق الحزمة والأداة اليدوية البديلة، ولا تعني أن التشغيل التلقائي يحتاج --apply.

## تحديث العرض: ملء الشاشة وومضة التحميل

صور المالك كشفت أن الفراغ الأسود كان baked-in داخل نسخ v1 التي جهّزناها، لا خطأ contentFit وحده. الملفات الحالية `*-cover-v2.mp4` وأغلفتها مقصوصة من الوسط بنسبة عمودية دون تمديد أو padding؛ يُفقد جزء من جانبي المشهد بشكل مقصود لملء الشاشة. `cover-manifest.json` هو المرجع الحالي؛ جدول أحجام v1 أدناه تاريخي. ملفات v1 لم تُحذف لأن روابطها قد تكون مخزنة في قاعدة أو كاش قديم.

الإقلاع التالي بعد نشر backend يحدّث فقط معرفات الحزمة المعروفة ذات video_url الأصلي المطابق إلى رابط v2 جديد، بعد backup مفحوصة، مع علامة `licensed_reel_test_pack_cover_v2` ضمن المعاملة. الغلاف يتحدث فقط إذا ما زال مطابقًا لغلاف v1. العناوين والحالة والعدادات وupdated_at والمحتوى المعدل يدويًا/المحذوف لا تُستبدل. الاسم الجديد يمنع استمرار immutable cache في عرض الملف القديم. التثبيت الجديد والأداة اليدوية يستعملان v2 مباشرة.

في تطبيق الهاتف: تُخفى سطح الفيديو المعتم حتى أول إطار لتبقى صورة الغلاف خلفه، ويظهر مؤشر التحميل فقط إذا استمر الانتظار 250ms أثناء التشغيل في foreground. الانتظار القصير لا يومض فيه المؤشر؛ الانتظار الطويل/الخطأ ما زال ظاهرًا وقابلًا لإعادة المحاولة. هذا debounce بصري، **لا prefetch ولا تقليل مثبت لزمن بدء الفيديو**. إعادة buffering بعد أول إطار قد تبقي الإطار الأخير مع مؤشر مؤجل. تحديث الغلاف/الفيديو يحتاج نشر الخادم، أما تعديل مؤشر التحميل فيحتاج نسخة تطبيق جديدة.

فُكّت ملفات v2 الخمسة بالكامل عبر FFmpeg دون أخطاء؛ اختبار hashes وmoov/mdat وRange يقرأ manifest الحالي. نجح 14 اختبار backend في 6 ملفات، و25 اختبار UI في 5 مجموعات، وفحوص الأنواع root/mobile والبناء الكامل. اختبارات UI استعملت --forceExit مع تحذيرات act/handles القائمة؛ لا قياس سلاسة على جهاز حقيقي. الترميز المقصوص زاد حجم بعض العينات: لا ندّعي أنه تحسين شبكة، ويجب قياسه على الهاتف. لا تغيير schema أو موقع تخزين أو واجهة ويب.

## ما أُنجز

المالك أجاز البحث عن فيديوات مرخّصة واستعمالها لاختبار الحركة. جُهزت خمسة ملفات **من ثلاثة مصادر أصلية** في مستودع MDN interactive-examples المثبت عند revision `13024db581b08fae11a0ca229497198b9b0534e7` بترخيص CC0 المرفق. لا ادعاء أنها خمسة إعلانات منتجات مستقلة: المشاهد أزهار وماء ومشهد فيلم أبيض وأسود من عينة friday، مع نسختين بديلتين للأزهار والماء. لا دعم أو رعاية أو ارتباط تجاري بالشخصيات المصورة.

الملفات ضمن `assets/media/reel-test-pack/`؛ لا تنزيل من مضيف خارجي أثناء التشغيل، ولا تعديل لفيديو demo السابق. مرجع كل مصدر وGit blob وSHA256 وتعديلات كل ملف في `manifest.json`، مع `NOTICE.md` ونسخة LICENSE الأصلية. لا تغيير للتخزين أو واجهة الويب. مسار `/media` القائم يخدم هذه الأصول بعد نشر الكود.

## الأداة اليدوية البديلة لإضافة الحزمة إلى قاعدة محددة

الأداة لا تستعمل DATABASE_PATH أو تفتح قاعدة افتراضية ولا تنشئ قاعدة مفقودة. عرض خطة فقط:

```bash
npm run reels:test-pack -- --database /absolute/path/to/existing-test.sqlite
```

بعد اختيار البيئة والتأكد من أن أصول `/media/reel-test-pack` منشورة ومخدومة، الإضافة الصريحة:

```bash
npm run reels:test-pack -- --database /absolute/path/to/existing-test.sqlite --apply
```

**--apply ينشر خمسة Reels مرئية لأي مستخدم لنفس backend**، وليس debug محليًا داخل هاتف واحد. العناوين تبدأ TEST / تجريبي، بلا أسعار أو روابط شراء أو product_id. يستعمل الناشر الرسمي الأول الموجود. لا تشغله على الإنتاج قبل الموافقة على ظهور محتوى الاختبار. لم يُشغّل هنا على قاعدة التشغيل ولم تُرفع ملفات عبر حساب CMS أو مضيف إنتاج. التشغيل التلقائي الجديد أعلاه هو الطريق الافتراضي بعد نشر backend.

الأداة:

- تتحقق من hashes ملفات الفيديو والأغلفة قبل الكتابة.
- تفتح القاعدة الموجودة فقط؛ لا تشغّل constructor أو migrations للتطبيق.
- تنشئ snapshot عبر SQLite backup API في `backups/pre-reel-test-pack-*.sqlite` بجانب القاعدة، بصلاحية 0600؛ تفحص integrity وFK قبل إدراج الصفوف.
- تُدرج داخل معاملة، بمفاتيح ثابتة، دون UPDATE أو DELETE. إذا استُعمل مفتاح محفوظ بفيديو آخر، تفشل ولا تستبدله. إعادة التشغيل تحفظ تعديلات العنوان/الحالة/الغلاف للمالك عندما يبقى نفس video_url.
- لا تحذف النسخ الاحتياطية، ولا تفعّل S3 أو retention. لا توجد أداة حذف جماعي للصفوف أو التفاعلات. بعد التجربة يمكن أرشفة/إخفاء الفيديوات من CMS المعتاد، دون إعادة تشغيل الأداة لاستبدال تعديلاتكم.

عند تطبيقها على بيئة مستخدمة، تُعامل كعملية صيانة مع مراجعة المسار وإيقاف الكتّاب حسب إجراءاتكم. النسخة الاحتياطية لا تبرر استرجاعًا فوق قاعدة مفتوحة.

## التحقق المنفذ

- فك كامل لكل ملف عبر FFmpeg محليًا بلا أخطاء، وليس فحص metadata فقط. FFmpeg وأصول التنزيل في `.cache`، لا اعتماد runtime جديد.
- اختبارات hashes وmoov/mdat وصور الغلاف وRange 206/MIME/Content-Range لكل فيديو عبر express.static.
- أداة الإضافة على قاعدة اصطناعية: dry-run لا يغير الصفوف، apply ينشئ snapshot وخمسة Reels، والقراءة العامة تراها؛ product_id فارغ، الصفوف القديمة محفوظة، إعادة التنفيذ تحفظ تحرير المالك، وتعارض المعرف/قاعدة مفقودة يفشلان بأمان.
- المجموعة المركزة: 3 ملفات / 8 اختبارات (pack، demo local media، public social reads). فحص TypeScript والبناء الكامل نجحا؛ تحذير حجم حزمة العميل القديم باقٍ. البناء لا يعني نشرًا أو تعديل واجهة الويب.

## التجربة في الهاتف بعد التفعيل

يلزم أن يصل الهاتف إلى backend البيئة التي أضيفت فيها الصفوف، وأن تكون أصول الفيديو منشورة فيه. تجديد APK وحده **لا يضيف صفوفًا لقاعدة الخادم**. تحديث البيانات في التطبيق أو إعادة فتحه قد يلزم بسبب staleTime.

اختبر: ضغط/رجوع متكرر، السحب بين الخمسة، أول فتح ثم إعادة الفتح، شبكة جيدة وضعيفة، pause/background/return. سجّل زمن API منفصلًا عن أول إطار والتقطيع والذاكرة. هذه الحزمة تجعل التجربة ممكنة، لكنها ليست قياس FPS فعليًا ولا إثباتًا للسلاسة على جهاز المالك أو شبكة الإنتاج.
