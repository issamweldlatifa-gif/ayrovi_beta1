# فصل قراءة التعليقات والعدادات

## التغيير

نُقلت قراءة `/social/comments` و`/social/counts` من SQL داخل HTTP إلى `src/magazine/socialEngagementReads.ts`، دون تغيير مخطط أو فهارس. HTTP يحتفظ بفحص صيغة targetId وأكواد الاستجابة وJSON، ووحدة المجال تعيد النتائج وتستخدم فحص ظهور الهدف المشترك مع كتابات التفاعل. ضُيّق اعتماد فحص الظهور إلى `get` فقط؛ لا معاملة كتابة مطلوبة للقراءة.

هذه دفعة تنظيم وصحة محدودة، ليست تحسين أداء مثبتًا. لا تغييرات في الاستضافة أو التخزين أو الدفع أو الواجهة.

## العقود المحفوظة وحدودها

- التعليقات: أحدث 100 صف وفق created_at DESC ثم عكسها للعرض زمنيًا؛ author الاحتياطي وparentId والتواريخ ونص التعليق كما سابقًا. HTTP يرجع 400 لمعرف غير صالح و404 للهدف غير الظاهر. لا pagination جديدة؛ التعليقات الأقدم خارج هذه النافذة لا تُرجع. عند تساوي created_at لا يوجد ترتيب ثانوي مضمون؛ لم نغيّر هذا العقد ضمن refactor.
- العدادات: تنظيف المعرفات ثم أخذ أول 60 **قبل إزالة التكرار** كما سابقًا، واستعلام تجميع واحد، وعدم استعلام قاعدة البيانات عند قائمة فارغة. تعاد أصفار للمعرفات غير الموجودة.
- حد 60 يقيّد عدد المدخلات في SQL لا عدد صفوف التفاعل المجمعة أو طول النص الخام الذي يصل إلى parser. لا ندّعي أن تكلفة التجميع ثابتة مع نمو البيانات.
- endpoint العدادات لا يتحقق من ظهور الهدف، كما سابقًا؛ لا يُرجع نصوصًا أو حسابات لكنه قد يعيد أعداد هدف غير ظاهر إذا عُرف معرفه. هذا قرار خصوصية سابق يحتاج مراجعة مستقلة، وليس تغييرًا صامتًا في هذه الدفعة.
- إصلاح طرفي صريح: خريطة العدادات أصبحت بلا prototype، حتى تُعامل المعرفات الصالحة مثل `__proto__` و`constructor` كمفاتيح بيانات عادية. سابقًا كان تعيين `__proto__` يغيّر prototype للكائن المحلي بدل إظهاره كمفتاح JSON؛ لا ندّعي وجود اختراق أو تغيير global prototype. بقية المفاتيح والنتائج محفوظة.

## الاختبارات

`tests/social-engagement-reads.test.ts`: خمسة اختبارات بوحدة المجال وHTTP:

1. fixture فيها 105 تعليقات مع مؤلف وردّ؛ مقارنة النتائج بـSQL السابق، حد 100 وترتيب النافذة وfallback.
2. صيغة targetId ورفض المنشور المسودة/المستقبلي/المفقود.
3. الأنواع الأربعة والأصفار وعقد JSON وإزالة التكرار.
4. حد المدخلات ومعنى slice-before-dedup وتجاوز SQL عند المدخل الفارغ.
5. مفاتيح prototype كبيانات عادية في المجال وعبر HTTP.

المجموعة المركزة: 13 ملفًا / 92 اختبارًا ناجحًا، تشمل كتابات التفاعل والتفضيلات وقراءات المحتوى والحماية وإعادة فتح القاعدة. اختبارات API الموبايل social/publicationFeed: ملفان / 17 اختبارًا ناجحًا. فحص TypeScript والبناء الكامل نجحا، مع بقاء تحذير حجم حزمة العميل.

## الباقي

قراءات اجتماعية أخرى ومسارات CMS لم تُفصل كلها. توقيت التفضيلات اختياري ولم يُفعّل أو يُوسّع هنا؛ لا CPU/RAM إنتاجي أو اختبار حمل/جهاز أو ادعاء سرعة في هذه الدفعة. ابتلاع أخطاء DDL في runSchema ومراجعات الفهارس والقراءات القديمة غير المحدودة ما زالت مفتوحة. تُراجع بالتدريج مع حفظ البيانات والعقود.
