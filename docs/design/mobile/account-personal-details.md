# Informations personnelles and notifications

The references informed the account summary, focused edit screens, horizontally scrollable delivery addresses, privacy controls, empty inbox illustration and black loyalty strip. The account identifiers and other personal details in the captures are not committed or bundled.

- **Personal details:** the summary uses the signed-in session data. The edit screen persists the account’s full display name, e-mail, avatar and existing opt-in, and keeps the phone read-only. Editing the e-mail still follows backend verification. There is no separate public customer number, first/last-name split or audience preference in the account model.
- **Delivery addresses:** the cards and editor share a query scoped to the active account, including checkout. The server supports one default delivery address, not separate delivery and billing defaults. Editing preserves the address id, postal code and recipient; deleting requires confirmation. The server selects the first default and handles promotion after deletion.
- **Password:** the dedicated screen checks matching confirmation, then uses the existing change API and immediately adopts the renewed session. The existing security screen retains contact verification and device controls.
- **Privacy:** account deletion uses the existing authenticated and CSRF-protected endpoint after an explicit, two-step confirmation and server acknowledgement. The UI distinguishes removal of the account from legal retention of transaction documents. Data access requests use published support channels; no export file, promised deadline, or Zalando account rules are implied.
- **Notifications:** the new original decorative illustration is shown only for a successful empty response. Real notifications, read actions, story links, and the account unread count remain. Signed-out visitors never see cached inbox content.
- **Loyalty:** the profile banner reflects the actual preview state (tier, confirmed points, points needed, and pending points). It uses the same in-memory sandbox as the loyalty screen, resets when the account changes, and does not award points on real orders. See [loyalty design](account-loyalty.md) for production prerequisites.
