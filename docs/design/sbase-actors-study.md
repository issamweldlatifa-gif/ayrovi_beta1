## 3) تفاصيل التفعيل الجديد: بطاقة AliExpress داخلية (logical_scrapers)

المدخل الموثّق: `productIds` (رقم المنتج من نتيجة الصورة) — أو روابط `/item/…`، مع:
- `includeDetails: true` ⇒ متغيّرات بـ**سعر ومخزون لكل SKU** + صورة SKU، **خيارات الشحن (كلفة + أيام وصول)**، المتجر، عدد المراجعات، معرض الصور، **المواصفات**، مسار الفئة.
- `includeDescription: true` ⇒ وصف HTML (ننظّفه كالـ1688).
- `currency: 'USD'`، `shipToCountry: 'US'`، `language: 'en'`، proxy افتراضي.

⇒ البطاقة تُفتح **داخل التطبيق** كالـ1688، والرابط الخارجي يبقى احتياطاً عند فشل البطاقة.
الزمن: غير مقاس — قياس حي أول مرة من حسابك بعد التثبيت. الثمن التقديري: ~0.003$/بطاقة.

**ما يتغيّر في التطبيق بعد التفعيل:** نتائج AliExpress تحصل على مُعرّف بطاقة (productId) ⇒ فتح داخلي بدل `Linking.openURL`؛ عند فشل التفاصيل نرجع للرابط الخارجي بصدق.

## 4) Alibaba — لماذا إلغاء البحث بالصورة

المسح الشامل لا يُظهر أي actor بحث صورة لـAlibaba يقبل base64:
- `devcake/scraper-by-image` يغطي 1688+Alibaba+AliExpress+3 أسواق لكن مدخله `imageUrls` (روابط عمومية) أو `imageFile` (ملف مرفوع عبر كونسول) — **لا base64 عبر API**، و3$/1K أغلى من موزّعينا الحاليين.
- المتبقي كلمات فقط: `scrapeunblocker/alibaba-search-scraper` 0.90$/1K بحقول غنية (نطاق سعر USD، شرائح كمية، **MOQ**، مبيعات، تقييم، مورّد Verified/Gold/Trade Assurance، مهلة التوريد) — كلمات إنجليزية، مناسب كمخزن كلمات لاحقاً إن أردت.

## 5) أمازون — الخلاصة

لا يوجد بحث صورة أمازون جدي بالمعايير (base64 + استقرار + ثمن معقول): `dev00` هشّ (مستخدمان، ناتجه قالب عام، رابط عمومي فقط)، و`devcake/amazon-ebay-scraper` بلا base64 وبحد أدنى 27 نتيجة/صورة (~0.0675$/صورة).

## 8) مقترح إعادة التصميم (رأيي)

### أ) عرض المنتج
- **بطاقة موحّدة داخلية لكل متاجر**: 1688 (موجود) + AliExpress (جديد). المعرض، المواصفات، الوصف، المتغيّرات (سعر/مخزون لكل SKU)، الشحن لكل متجر Ali، المورّد وتقييمه.
- السعر المعروض = محرّك التسعير المحلي دائماً (قاعدة ثابتة)، وسعر المصدر معلومة لا قرار.
- الرابط الخارجي يبقى زراً ثانوياً «فتح في المتجر»، لا مساراً أساسياً.

### ب) وقت الانتظار — صدق في كل شاشة
- مؤشر مراحل بالأزمنة الموثقة: بحث صورة 1688 ~20–40ث · بحث Ali ~20–60ث · بطاقة 8–12ث بلا وصف / ~32ث مع الوصف.
- **خيارات الوصف (32ث)** — القرار لك:
  1. يبقى دائماً كما هو الآن (بطاقة كاملة، فاتورة واحدة) — **توصيتي**، مع مؤشر زمن صادق؛
  2. مفتاح بيئة `APIFY_DETAIL_INCLUDE_DESCRIPTION` (تشغيل/إيقاف بلا نشر كود)؛
  3. بطاقة سريعة + زر «تحميل الوصف» يدير تشغيلاً ثانياً (+0.009$ و+30ث) — لا أنصح (تعقيد وفاتورتان).

### ج) كمية النتائج
- `APIFY_IMAGE_MAX_RESULTS` افتراضي **10** (المتفق عليه) + اختيار في الشاشة (5/10/20) مع التكلفة التقديرية قبل البحث:

| الكمية | 1688 صورة (topapi) | AliExpress صورة (piotrv1001) |
|---|---|---|
| 5 | 0.001$ | 0.02$ |
| 10 | **0.002$** | 0.02$ |
| 20 | 0.004$ | 0.02$ |

(الـAli ثابت لكل صورة أياً كانت الكمية — ترشيح الكمية يخصّ 1688.)

### د) فلترة ذكية — من الحقول المستلمة فقط، بلا اختراع
- Chips عميلة (صفر تكلفة): «متوفر» · «MOQ ≤ 2» · «سعر ≤ X» · «الأكثر مبيعاً» (مبيعات Ali) · «تقييم ≥ 4.5» (Ali) · «يدعم الدروبشيب» (1688).
- إزالة المكرر (عنوان/صورة متطابقة عبر المتاجر)، وترتيب: أفضل مطابقة (ترتيب المصدر) / الأرخص / الأكثر مبيعاً.
- أي حقل غائب لا يظهر فلتراً — بصدق.

### هـ) خطة التنفيذ
1. **المالك**: تثبيت #1 (+اختياري 2–4) + قياس حي واحد.
2. **أنا**: مفتاح الكمية + بطاقة AliExpress الداخلية (مترجم جديد + تعيين داخل التطبيق) + مؤشر الأزمنة + الفلاتر الذكية + الاختبارات الكاملة (جذر/موبايل/jest/design) — القديم لا يتوقف أبداً قبل إثبات الجديد.
3. Gates ثم push ثم CI ثم قياسك الحي الأخير.
