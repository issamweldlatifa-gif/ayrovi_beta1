## 2 · Commercial 1688 APIs (بائعو بيانات تجاريون)

| البند | الوصف |

## 4 · Custom Data Acquisition (سحب ذاتي)

| البند | القيمة |
|---|---|
| الوظائف | كل الوظائف ممكنة نظرياً (بحث/صورة/تفاصيل/SKU/مورّد) |
| Reliability | استثمار صيانة مستمر: دورات حظر، proxies صينية، بصمات متصفح — يتدهور بلا فريق |
| Rate Limits | تفرضها حماية 1688 المتغيرة — Unknown ومتقلبة |
| Cost | ثابت عالي (هندسة+بنية) + متغير منخفض — يُربح فقط فوق عتبة حجم (D17) |
| Legal/Operational | **ضد شروط 1688 غالباً** + عبء تشغيل 24/7 |
| **دليل ارتباط بـSoorce** | **الأدلة العامة متسقة مع هذا الاحتمال (شارات ويب + مرور خام) لكنه غير مثبت — قد يكون actor خاص غير مدرج** |

## 5 · Authorized Sourcing Providers (خدمات توريد بواجهات/وكلاء)

| البند | القيمة |
|---|---|
| الوظائف | بشرية+API: توريد كامل، تحقق حي، QC، شحن — لا «بطاقات بيانات» |
| Reliability | حسب العقد |
| Cost | هامش مدمج (قياسنا على Soorce نفسها: 28–56% تنازلي) |
| Legal/Operational | عقود خدمة؛ لا ملكية للبيانات غالباً |
| **دليل ارتباط بـSoorce** | **لا شيء — وSoorce نفسها مثال على هذه الفئة كخدمة، لا كمزود بيانات** |

## 7 · خلاصة مبدئية للتصميم (لا للتنفيذ)

1. **النواة الحالية تبقى**: `sourabhbgp/1688-scraper` — الوحيد المجرّب حياً عندنا بكلفة مقيسة وسقف قياس (لا purchases جديدة؛ قاعدة حماية رصيد Apify).
2. **مرشح بنش وحيد** عند الحاجة: `nice_dev` (بحث صورة + كلفة أقل ×7–13) عبر بروتوكول البنش الخماسي في `sbase-sourcing-identity.md` §4 — بلا إنفاق قبل اعتماد المالك.
3. **Official API**: مسار شراكة فقط إن قرر المالك فتحه — يفكّ عقدة «شارات الويب» ويقلل مخاطر community actor.
4. **Custom ذاتي**: قرار ما بعد P2 بأرقام حجم حقيقية (D17 عتبة) — لا يبدأ الآن.
5. كل خيار يُدرج في ZPIM كـ**connector قابل للتبديل** خلف عقد موحّد — استقلالية S BASE عن المزود (D14/D15) هي الضمانة البنيوية.
