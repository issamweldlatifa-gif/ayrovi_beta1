# D13 — Product Data Processing Architecture
**الحالة:** مسودة v1.0 — بانتظار مراجعة المالك. **دراسة تصميم فقط — NO CODE.**
**المنهج:** كل مرحلة في خط المعالجة مقرونة بشاهد Soorce (يفعل/لا يفعل/يفشل) + القرار المعماري لنا. الشواهد: `docs/design/soorce-investigation.md` + `soorce-artifacts/` + تجربتنا الحية في `src/sbase/` (قراءة مرجعية فقط — لا تعديل).

---

## خط المعالجة المرجعي (10 مراحل)

```text
Actor/API payloads (خام)
   │ 1. Ingest ── 2. Shape Detection ── 3. Field Mapping (per source)
   ▼
Raw Product Store (غير قابل للتغيير، TTL)
   │ 4. ID Normalization ── 5. Variant Extraction ── 6. Translation
   │ 7. Image Pipeline ── 8. Quality Validation ── 9. Dedup
   ▼
SbaseItem v2 (عقد موحّد) ── 10. Enrich & Publish ──► S BASE engine
```

## المراحل العشر — الشاهد والقرار

| # | المرحلة | شاهد Soorce | قرارنا المعماري |
|---|---|---|---|
| 1 | **Ingest خام** | يمرّر الخام دون تخزين ظاهر في البحث (عدّادات حية) | **نخزن الخام** (Raw Store غير قابل للتغيير، TTL ~60d): إعادة معالجة عند drift، تشخيص، bench — تكلفته ضئيلة (KB/بطاقة) |
| 2 | **Shape Detection** | مخططان يمرّان غير موحّدين (بحث vs تغذية — جدول فروق D11-B) | كاشف مخطط صريح لكل رد actor؛ المخطط غير المعروف ⇒ error صادق + quarantine، لا تخمين حقول |
| 3 | **Field Mapping** | لا توحيد ظاهر | mapper لكل مصدر → عقد موحّد؛ الحقول الموثقة فقط (قاعدة actors-study: لا افتراض حقول) |
| 4 | **ID Normalization** | offer ID 1688 = مفتاح كل الطبقات عندهم (API/URL/صور/sitemap) | نفس المبدأ: `offer_id` مفتاح عالمي داخل ZPIM؛ معرّف داخلي موازٍ فقط عند تعدد المصادر (P2) |
| 5 | **Variant Extraction** | متغيرات بثمن/صورة لكل خيار؛ لكن المقاسات تسرّب خاماً (فشل jin→kg) | مصفوفة SKU كاملة (لون/مقاس/ثمن/صورة/توفر) من تفاصيل الactor؛ نصوص المواصفات تمر عبر طبقة وحدات |
| 6 | **Translation** | استعلام→zh مثبت؛ محتوى→MT بلا معجم = فشل موثق | **معجم وحدات وصناعة** إلزامي (斤→كغ، قطع/دستة/سلة)؛ اتجاهان: سؤال ar/fr/en→zh قبل النداء، محتوى zh→ar/fr بعد التوحيد |
| 7 | **Image Pipeline** | مرآة Supabase للبطاقات + hotlink للمتغيرات | مرآة انتقائية (الصورة الرئيسية للبطاقة المختارة فقط — ضبط تخزين) + hotlink للبقية + alt موصوف |
| 8 | **Quality Validation** | لا طبقة QC معلنة — score خام يمرّ | قواعد رفض/عزل: سعر خارج نطاق tiers، MOQ غير متسق مع `quantity_begin`، بلا صور، عنوان فارغ ⇒ quarantine بكود صادق |
| 9 | **Dedup** | `is_ad` فقط؛ لا دليل dedup | `offer_id` dedup داخلي فوري؛ عبر-المصادر P2 (مطابقة Yiwugo↔1688) |
| 10 | **Enrich & Publish** | إخفاء مورّد + حقول ثقة خام تمر | إثراء موثّق: `trust{shopYears,isSuperFactory,repurchaseRate,saleInfo}` + **خيار إخفاء المورّد في العرض العام مع بقاء الرابط الكامل لـCRM** (قرار منتج للمالك) |

## قرارات حاكمة مستخلصة من الشواهد

1. **لا نسخ فشل Soorce**: ترجمة بلا معجم تنتج «90–105 kilograms» — طبقة الوحدات شرط إطلاق لأي ترجمة محتوى.
2. **لا توحيد ناقص**: مرور مخططين خامين كما يفعلون يعني سلوكاً متذبذباً في الواجهة — كاشف المخطط (مرحلة 2) يمنع ذلك عندنا منذ اليوم الأول.
3. **التخزين الخام ليس رفاهية**: Soorce يستحيل علينا تحليلها بلا خام؛ Raw Store يجعل كل تشخيص مستقبلي ممكناً بربع نداء.
4. **العقد أولاً**: كل مرحلة تنتقل بعقد `SbaseItem v2` موثق الإصدار (D14) — نفس الانضباط الذي أثبته الـE2E الثلاثي (AYR-299819).
