# D16 — Commerce Core Integration Boundaries
**الحالة:** مسودة v1.0 — بانتظار مراجعة المالك. **NO CODE — توثيق حدود المسؤوليات ومنع تكرار المحركات.**

---

## جدول الحدود (كما حددها المالك)

| النظام | مسؤول عنه | **ليس مسؤولاً عنه (منع التكرار)** |
|---|---|---|
| **ZPIM** | جمع بيانات المنتجات ومعالجتها وتوحيدها — كتالوج وكاش وترجمة | أي منطق سلة/طلب/دفع/تسعير تجاري؛ أي قرار عرض للعميل |
| **S BASE** | اكتشاف المنتجات ومعلومات المصدر (lanes/selection/scoring) + واجهة المصدر للتجارة | لا سلة ولا دفع ولا طلبات؛ لا نداءات مزودين مباشرة (عبر ZPIM فقط) |
| **Commerce Core** | السلة والطلبات والتسعير التجاري والدفع والعربون | لا منطق sourcing ولا استدعاء مصادر؛ لا يعرف Apify/1688 |
| **CRM** | استقبال معلومات الطلب ومصدر المنتج والمتغيرات المطلوبة (حجم/لون/ملاحظة/كمية لكل فرعية) | محرك لا مستقبل — لا يعيد تسعيراً ولا يعيد اكتشافاً |
| **المستودعات والشحن** | العمليات اللوجستية (استلام/QC/تغليف/تتبع) | لا تسعير تجاري؛ تقرير QC يخدم قرار الطلب لا يصدره |

## نقطة الالتحام الوحيدة بين عالمَي البيانات والتجارة

**`SbaseItem` → سطر سلة** — المجرّب والإثبات الحي:
- الـE2E الثلاثي: `tests/commerce-core-mixed-cart-e2e.test.ts` (AYR-299819) — سطر S BASE خام 1688 بـلون/مقاس/ملاحظة يدخل سلّة موحّدة مع AYWEBS عبر checkout واحد.
- عقد المتغيرات يُسجَّل قبل التجارة: `recordVariantContract` (DI من `src/server.ts`).
- حالات السطر: `PENDING_SELECTION` / `PENDING_MANUAL` — المراجعة البشرية قبل أي عربون (تسلسل المالك).

## الحدود التجارية المرتبة (تسلسل المالك عبر الحدود)

```text
pick (S BASE) → variants (ZPIM عقد → S BASE عرض) → cart (Commerce Core)
  → human review (Back-office + CRM يستقبل المصدر والفرعيات)
  → verify supplier/price/availability (مراجع بشري، بيانات ZPIM + CRM)
  → deposit (Commerce Core) → procurement/logistics
```

## قواعد صارمة ضد تكرار المحركات

1. لا منطق دفع/عربون داخل S BASE أو ZPIM — حصراً Commerce Core (المثبت: checkout موحّد + كود `PENDING_SELECTION` فقط يمرّ).
2. لا استدعاء مزودين من Commerce Core — طلب «معلومات مصدر» يمر عبر S BASE/ZPIM وصولاً لـCRM.
3. CRM مستقبِل معلن الحقول — لا يعيد تنفيذ اكتشاف أو تسعير.
4. أي ميزة جديدة تُسأل أولاً: «أي صندوق من الجدول؟» — إن احتاجت صندوقين ⇒ واجهة بينهما بعقد، لا دمج.
5. Release ≠ refund وD4 بالمجموعات المرآة — قرارات Commerce Core معتمدة، لا يعيد ZPIM/S BASE فتحها.
