# AYWEBs — Amazon/Zalando recovery and store isolation (investigation)

Status: investigation / local baseline, not a completed restoration. 30 October 2026.

## Evidence and scope

The supplied screenshots show an older website experience with selectable size cards and an app screen showing an Amazon server timeout. They do not identify the exact source commit, APK/backend version, product URLs or network response. They do not prove which capture-script change caused the app failure. Website and native flows must be traced separately.

- At `85069d3` (29 October), the native store browser explicitly started passing `readOnlySelection` to `AddToCartSheet` (`apps/mobile/app/aywebs/browser.tsx`). The corresponding sheet renders current captured selection and a return-to-store action instead of interactive variant controls. This is an independently demonstrated functional change in the app, not proof of the timeout's cause. The user now requests interactive options again for Amazon and Zalando. Other stores must not silently change.
- Earlier capture candidates: `7cb268e` (Amazon/Zalando reader, 25 October) and `ecaff12` (Amazon size/color quote publication, 26 October). The latter precedes SHEIN/Aliexpress v2 and subsequent Temu changes, but Git history alone cannot prove either candidate was the exact build displayed by the user, nor that a wholesale rollback is compatible with current quote/selection and anti-stale evidence rules.
- Merchant adapters exist at `src/aywebs/adapters/{amazon,zalando,shein,temu,aliexpress}.ts`. They have common base/contract/normalization/resolution dependencies. `src/aywebs/captureReaders/` defines profiles, not independent extraction scripts. `buildAyWebsCaptureScript` embeds the same `AYWEBS_CAPTURE_SCRIPT` in every profile. A change in this shared core can therefore affect every merchant. Profile-specific cache/header alone is not isolation. Some older clients use the unparameterized legacy script.
- The native add-to-cart path still checks selection, availability and server resolution / signed quotes; putting interactive controls back must not reuse proof for a different variant or introduce an inferred price, stock or SKU. Amazon may require navigating a variant URL and Zalando may require price evidence for each size. Unknown is not in stock.
- The screenshot's timeout could originate from multiple steps (capture, resolve, network or API); no logs were supplied and the precise cause is unconfirmed. Do not treat a UI rollback as a timeout fix.

## Proposed implementation and acceptance gates

1. Record source hashes and retain current legacy bundle / per-store adapters as rollback point. Compare historical Amazon/Zalando capture output against the current profile with saved, sanitized fixtures from the *same* actual pages and selections, plus exact-price/stock/cart tests. Prefer an evidence-based port over replacing the whole shared script and losing later security and compatibility fixes.
2. Extract independent merchant readers into separately owned source modules and compose each merchant bundle only from common, versioned safety/contract helpers plus that merchant's reader. No Amazon code in Zalando, TEMU, SHEIN or AliExpress output and vice versa; disallow cross-store module imports and add isolation tests that fail when another merchant bundle changes unexpectedly. Preserve the old no-store endpoint until compatibility with older clients is established. Take care: a shared helper change can still affect all merchants; freeze/version helpers or require all-store regression tests for any shared contract change. Isolate existing adapters' merchant decisions without severing common security checks.
3. Restore interactive choice mode **for Amazon and Zalando** while leaving other stores' current behavior untouched. Test dimensions beyond color/size (capacity, type), unselected fields, unavailable values, changes in price/stock, correct product images, quantity and exact selection. Show only merchant-provided evidence; disable unavailable choices. A selection must be associated with its exact verified capture or server-signed quote before addition.
4. Run cross-store suites plus mobile unit/UI integration, script ES5 and WebView compatibility, same-page selection and stale cache regressions, API/cart idempotency and zero/invented price negatives. Compare timings before/after, not just test outcomes. Then test actual products on a real device and check network response at the failing step. Absence of fixture/device evidence is a release blocker for a claim that live behavior is restored.
5. No deploy, push, database/production settings changes, or real orders without explicit permission. Roll back locally per store using its previous immutable reader version; never revert the entire shared script or data blindly.

## Implementation started — Amazon first

- `src/aywebs/storeScripts/amazon.ts` is a **non-routed prototype**, derived from the historical `ecaff12` reader, with non-Amazon conditional capture branches removed. Host normalization was extended for mobile prefixes and the prototype returns no capture on non-Amazon hosts. It is a separate executable script owned by Amazon; it does not import the shared capture core. The existing `AmazonAdapter` is already registered and a test exercises its mobile-product classification. This prototype does not activate it for requests and does not alter the legacy reader, so current merchants and old applications are unchanged.
- `tests/aywebs-amazon-recovered-mobile.test.ts`: checks mobile-host product recognition, Amazon price from the repository fixture, synthetic selected/unavailable twister choices and rejecting Zalando/deceptive hosts. A temporary comparison using the existing Amazon subset of `aywebs-capture-amazon-zalando-2026-10-25.test.ts` against the prototype passed 7 Amazon tests (8 unrelated tests skipped). These checks do not establish compatibility with all current quote and selection logic or a live mobile WebView.
- Local validation: `npm run typecheck` passes; 4 targeted test files, 37 tests pass, including existing Zalando and SHEIN/TEMU tests. No network, production data, deploy or push. Historical Amazon fixtures described above remain absent.
- **Not complete:** script serving still uses the shared legacy core, the read-only native sheet remains unchanged, and the independent Zalando reader has not yet been built. Further work must connect the Amazon prototype only after its mobile capture/quote/cart compatibility tests, then construct a separate Zalando script and activate it independently; the requested rule is no shared executable script between stores. The previous suggestion to compose all readers from shared executable helper modules is superseded by that rule. Shared interface definitions and independent server validation may still be necessary, but do not constitute a shared WebView capture script.

## Follow-up: image, quantity, quote and latency (local only)

The user's screenshots show blurred images, missing TND quotes, a spurious `Option choisie : 1` and slow navigation/extraction. They do not identify exact product URLs, server response or deployed build; causes cannot be established from screenshots alone.

- Reproduced two concrete reader defects with mobile-URL synthetic DOM fixtures: metadata thumbnail won over a published larger product gallery image, and a selected quantity `<option>1</option>` was reported as a variant. Both failed before the fix and pass after. Amazon reader version 3 prioritizes the largest published dimensions from the product gallery, then a published high-resolution image/source; it does not manufacture image URLs or use unrelated dynamic images. Quantity selects are filtered without excluding numeric sizes. This changes only Amazon's dedicated script.
- No product-specific price/timeout cause was proven. In the native app the sheet opens from the local capture and starts `loadQuote`; that plan may sequentially request capture+selection, capture only and server-only, each subject to API timeout. `waitForPageIdle` can also wait up to 8 seconds. These are possible delays, not measured causes of this user's failures. No pricing formula, quote safety rule, timeout or navigation behavior was changed; do not invent a TND price or claim price/timeout is fixed.
- Local indicative microbenchmark: Node 22.23.4, JSDOM, one saved 678 KB Amazon mobile HTML fixture, same in-memory DOM, 3 warm-ups, 20 interleaved executions per version: before median 67.01 ms/p95 83.76 ms; after 64.42/71.02 ms. Small single-run sample, not Android WebView, network, checkout, or a demonstrated end-to-end speed improvement. Neither browser opening nor merchant/server response was measured.
- Node typecheck and 8 targeted suites: 102 passed, 13 skipped (missing real-page fixtures). No deploy/push or live-device test of reader version 3. To investigate unresolved errors, collect exact product URLs, chosen options, timestamps, application build and privacy-safe resolve/timeout diagnostics; never send user credentials. A device test with the changed server is still required.

## Zalando isolation — local follow-up, not released

`storeScripts/zalando.ts` is a standalone ES5 reader derived from the structured-only legacy reader: other merchant-specific capture branches were eliminated, the Zalando profile is fixed to version 2, and an explicit Zalando host guard rejects other domains. It does not import Amazon or the legacy executable; the Zalando adapter remains separate. It is a compressed/beautified extraction and is harder to maintain than handwritten source, so future changes need particular care. Compatibility calls without a store ID and other merchants still use the legacy script; full isolation of all merchants remains unfinished.

Root typecheck and server build succeeded; 10 targeted suites passed 128 tests. The dedicated reader was exercised for color scope, per-size price/stock, ambiguity, mobile page, host isolation and endpoint version. The separate variant-matrix suite passed the Zalando synthetic fixture through HTTP resolve with distinct prices and out-of-stock behavior. These are local fixtures/test database, not a live store or device. No latency improvement is claimed.

**Release blocker found in broader regression:** `tests/aywebs-variant-price-matrix-benchmark.test.ts` fails its Amazon 2D-matrix case because the previously committed standalone Amazon reader does not provide `variantMatrix`; the Zalando case passed. `git show HEAD:src/aywebs/storeScripts/amazon.ts` confirms the omission predates this Zalando change. The first transformed Zalando attempt also failed tests and was corrected locally before the passing runs; no deployment was made. Fix and retest the Amazon matrix regression before release rather than weakening the assertion. No new push was made for Zalando.

## Amazon matrix and image regression — follow-up

The standalone Amazon reader now carries a bounded per-ASIN variant matrix, joining published variant identities to card, buybox and observed network facts; unknown prices do not inherit the page price. If two ASINs have the same displayed attributes, the matrix row deliberately loses price, availability, identity and image instead of merging unrelated facts. A synthetic regression test failed before that guard and passed after. Amazon reader metadata is now version 4. Known Amazon banner/logo URLs are filtered out from product images, restoring an existing image-quality test. The multi-store matrix suite now passes both Amazon and Zalando cases, including an unknown-price negative and Zalando HTTP resolution. Both standalone reader bundles parse as ES5 using Acorn; this is syntax verification, not a test on an old physical WebView.

The first comprehensive root run identified four failures: two stale reader-version/profile assertions, and the Amazon banner regression, plus the previously fixed version assertion. All affected suites were rerun successfully after correction. Mobile typecheck, 1,117 mobile unit tests and 174 component tests passed; Jest needed force exit and emitted React act/open-handle warnings. These results do not prove live device behavior, end-to-end latency, or the cause of the user's TND error. Amazon and Zalando are individually isolated; other merchants and old store-less clients still use the legacy script.

Final local root regression rerun after the fixes: 253 suites, 3,240 passed and 17 skipped. Root typecheck and server build passed. This is not live-merchant or production verification.
