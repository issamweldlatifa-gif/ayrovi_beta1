# خطة دمج هوية أيروفي A — 21 سبتمبر 2026

## القرار المعتمد
وافق المستخدم صراحة على Zalando Sans للاتينية والأرقام + Noto Sans Arabic للعربية كالقائمة الوحيدة لخطوط الواجهة. الأبيض الأساسي #FFFFFF والأسود الأساسي #000000؛ تحفظ ألوان العلامة والحالات الوظيفية. هذا اعتماد استخدام لخطوط مرخصة OFL، لا ادعاء ملكية تصميمها.

## قواعد العمل
- يبدأ التنفيذ بخط أساس ثم تغييرات قابلة للمراجعة، لا استبدالات عشوائية لمنطق الأعمال.
- لا تغييرات في تسعير الطلبات أو العملات أو قواعد الخصومات بسبب العرض الطباعي.
- لا تشغيل دفع أو بريد/SMS فعلي، ولا تعديل بيانات إنتاج. الدفع إلى GitHub مشروط بطلب المستخدم؛ وقد أجازه بعد إتمام الفحوص في الجولة الأخيرة.
- لا تغيير الشعار أو الأيقونات أو هندسة الواجهة إلا عند إصلاح عيب موثّق ناشئ عن الدمج.
- مصدر هوية واحد، مخرجات مولّدة واختبارات تمنع الانحراف. لا يكفي CSS أخير يخفي العيوب.
- خط احتياطي generic من المتصفح ضرورة عند فشل التحميل أو وجود محارف غير مدعومة؛ ليس عائلة تصميم ثالثة. لا يمكن فرض الخط على UI المتصفح أو نص داخل صورة أو iframe خارجي أو عميل بريد لا يدعم webfonts.
- فحص CI يمنع التغيير المخالف عند تشغيله؛ حماية فرع GitHub وجعل الفحص Required تحتاج إعدادات المستودع التي ليست متاحة هنا.

## المراحل وبوابات القبول
### P0 — الحصر وخط الأساس
حصر CSS/TSX، الإعدادات وCMS، الإدارة، الصفحات الثابتة، الفواتير والبريد، تعريفات Tailwind، loaders وCSP.
بوابة: typecheck وbuild ومجموعة الاختبارات قبل التعديل، وتسجيل الثغرات المعروفة دون إخفائها.

### P1 — عقد الهوية والموارد
تحديث identity.json، نسخ ملف Zalando الأصلي والتحقق من SHA-256 والرخصة، الاحتفاظ بالعربي المعتمد، حذف موارد خطوط الإنتاج غير المعتمدة. توليد CSS/TS مشترك من المصدر نفسه. مستويات display/heading/body/label/caption/price/table-number بأوزان وأرقام معزولة، لا وزن ثقيل لكل نص.
بوابة: فحص البصمات والتراخيص والتباين وصحة المخرجات المولّدة.

### P2 — دمج العميل والإدارة وإغلاق الإعدادات
ترحيل الخطوط المكتوبة صراحةً، إزالة Google Fonts وتحميل خارجي، قفل preset/fonts عند القراءة والكتابة والتطبيع، تحديث واجهة الإدارة لتوضيح القفل. تحديث الأبيض والأسود والحياد الرمادي من دون تغيير ألوان البرتقالي/النجاح/الخطر. المحافظة على الوضع الداكن وقابليته للقراءة.
بوابة: اختبارات تطبيع إعدادات قديمة وعدائية، اختبارات الواجهة والهوية والأزرار وحفظ المحتوى، ثم build/typecheck.

### P3 — المخرجات والحراسة الآلية
الصفحات القانونية والثابتة، الفواتير والطباعة والبريد الذي ينشئه النظام. منع الخطوط غير الرسمية في كود التشغيل عبر فحص قابل للاختبار ضمن build وCI، فحص موارد الخطوط ومصادر الشبكة، وثيقة للمطورين.
بوابة: اختبارات رفض إضافة CSS/TSX/Tailwind/HTML مخالف، الحفاظ على HTML escaping وعدم تنفيذ معلومات التاجر كنمط CSS. توثيق حدود البريد والخدمات الخارجية بوضوح.

### P4 — اختبارات المتصفح والانحدار
شاشات العميل الرئيسية والحساب والسلة والدفع وLens والمساعد، الإدارة، لغتا AR/FR، أرقام وأسعار تتغير بعد البيانات، عرض هاتف وسطح مكتب. قياس الخط المحمّل فعليًا بعد document.fonts.ready، لا الاكتفاء باسم CSS. اختبار تركيز وتعطيل وأزرار وحالات خطأ. تشغيل اختبارات الأمان الموجودة وتدقيق اعتماديات دون ترقيات كبرى عمياء.
بوابة: نجاح الاختبارات، صور/تقارير قابلة للمراجعة، سرد دقيق لما لم يُختبر، لا إعلان أمان شامل أو أداء محسّن بلا قياس.

### P5 — إقفال مرحلي وتسليم
توثيق الملفات والنتائج والحدود وخطوات النشر/التراجع. لا نشر إنتاج قبل المراجعة. أي عيب قديم مستقل كبير يفصل عن الدمج ولا يصلح بتوسيع نطاق غير قابل للضبط.

## نقاط اكتشفها الحصر
- طبقات متعارضة: Inter، Space Grotesk، Amiri، DM Serif Display، خمس هويات اختيارية في Interface Studio، وخطوط مستقلة في الفاتورة والبريد والصفحات الثابتة.
- font-mono في بيانات الإدارة/الحساب قد يفعّل خط Tailwind الافتراضي؛ ينبغي ترحيله إلى أرقام رسمية متساوية العرض بدل خط جديد.
- بعض tokens تاريخية؛ يجب المحافظة على الاختبارات الوظيفية وتحديث الاختبارات التي تفرض الهوية السابقة فقط.
- وصول محتوى API لا يستلزم حقه في اختيار font-family. قفل الهوية يجب أن يشمل التطبيع على السيرفر والعميل، لا المعاينة وحدها.
