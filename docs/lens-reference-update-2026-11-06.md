# Lens — شبكة النتائج والتحديد والتحميل

## التنفيذ

- تطوير Lens الحالية لكل طرق الإدخال، دون تغيير Navigation أو مسار فتح المنتجات داخل AYWEBs.
- شبكة عمودين وصور 2:3، علامة أو متجر بخط أوضح، عنوان بخط عادي محدود بسطرين، وأسعار حقيقية عبر LensPriceBlock القائم. لا نقاط Carousel داخل البطاقة.
- حذف شرح «Touchez une carte…» وإزالة ترجمته غير المستخدمة؛ فلتر العنوان وراء زر واضح بدل حقل مفتوح دائمًا. الإبقاء على المفضلة وفتح المنتج.
- الخانة الوحيدة في الصف الأخير تبقى نصف عرض بدل التمدد إلى عرض الشاشة.
- Sans photo (mots-clés/liens), résultats directement sous le Header, sans grande zone noire vide ni saut de hauteur à la fin du chargement.
- Shimmer بلون محايد عبر إضاءة متحركة فوق الرمادي، للسكلتون والصورة التي لم تصل بعد. يحترم إعداد تقليل الحركة ويتوقف عند فك المكوّن.
- تحميل كل صورة مستقل، مع انتهاء الانتظار عند النجاح أو الفشل وإعادة محاولة منفصلة؛ لا انتظار `Promise.all` للصور.
- إعادة استخدام SSE الصور القائم: بطاقة `card` تُعرض فور وصولها، مع خانات تحميل إضافية أثناء استكمال البحث. الحفاظ على نفس مكوّن الشبكة بين المرحلة الجزئية و`done` لتجنب إعادة تركيب البطاقات عند النهاية. لا تأخير اصطناعي لعرض نتائج جاهزة.
- إخفاء بطاقة الوصف التعريفي فوق النتائج أثناء البحث، مع بقاء تقدم حقيقي موجز وحالة البحث والإلغاء.
- إعادة استعمال تحديد ROI الفعلي: سحب الوسط للتحريك، الزوايا للتحجيم، وتعتيم الخارج. إضافة إرشاد بصري أثناء السحب ونبض أثناء البحث؛ إلغاء طلب المنطقة السابقة فور تثبيت اختيار جديد، قبل مهلة debounce، لمنع نتيجة قديمة من ملء اختيار جديد.
- فصل أزرار الصورة والمفضلة وإعادة التحميل لتجنّب أزرار متداخلة في Expo Web.

## البحث المرجعي

توثيق Google الرسمي يصف جرّ زوايا إطار البحث لتحديد جزء من الصورة، وجرّ وسطه لتحريك المنطقة. اعتمدنا هذا المبدأ على مكوّن التحديد القائم، ولم ندّعِ وجود كشف أجسام أو صناديق AI لا يرسلها الخادم.

## التحقق والحدود

- TypeScript التطبيق ناجح.
- اختبارات منطق التطبيق كاملة: 1134 ناجح.
- اختبارات مكونات React Native كاملة: 204 ناجح، 38 مجموعة. `--forceExit` بسبب handles باقية في مجموعة Jest الكاملة؛ ليست تجربة على هاتف.
- اختبارات جديدة للصور المستقلة، الفشل وإعادة المحاولة، بطاقة جاهزة مع خانات انتظار، وحدث SSE قبل done ثم إنهاء خانات التحميل.
- اختبار Expo Web بعروض 360/390/768: ظهور السكلتون، شبكة النتائج، صف أخير نصف عرض، فلتر العنوان، وإزالة الشرح، دون page errors. استُعمل رد API اختباري وصور محلية في المتصفح فقط؛ لا تُحفظ بيانات QA في التطبيق أو قاعدة البيانات.
- مسار الصورة يرسل بطاقات SSE تدريجيًا بالفعل. مسارات الكلمات والرابط التي تعيد JSON تنتظر رد البحث نفسه، لكن **لا تنتظر اكتمال كل الصور**؛ لم نغيّر عقد الخادم إلى streaming نصّي أو نزعم تنفيذ ذلك.
- لا ادّعاء قبول Android/iOS أو تجربة Live بكاميرا هاتف حقيقي: أدوات الأجهزة غير متاحة في البيئة. يلزم التحقق الأصلي من السحب والذاكرة وتقليل الحركة والشبكات البطيئة.
