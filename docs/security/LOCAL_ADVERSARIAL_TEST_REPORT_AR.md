# تقرير الجولة المحلية للاختبارات الهجومية

## خلاصة تنفيذية
نُفّذت اختبارات هجومية محدودة على نسخة محلية من كود السيرفر، لا على Render. النتيجة: **198 اختبارًا ناجحًا في 17 ملفًا**، منها **57 حالة جديدة** أضيفت لهذه الجولة. لم تكشف الحالات الجديدة عن تجاوز أمني ناجح ضمن نطاقها. هذا ليس تقييمًا شاملًا أو نسبة أمان، ولا شهادة اختبار اختراق خارجي.

المراجعة السابقة وإصلاحاتها: [تشديد الحماية الأولي](SECURITY_REVIEW_AND_HARDENING_AR.md).

## بيئة وحدود التنفيذ
- قاعدة SQLite في الذاكرة، حسابات وجلسات وعناوين مخصّصة للاختبار، تُغلق عند النهاية.
- اختبارات العزل الجديدة ترسل HTTP عبر Supertest إلى Express وcreateCustomerRouter الحقيقي؛ ليست mock لقرارات المصادقة أو SQL. ليست أيضًا نسخة كاملة من reverse proxy أو إعدادات بيئة الإنتاج.
- اختبارات SSRF تستعمل محلّل DNS/نقل محقونين؛ لا اتصال بعنوان داخلي أو خدمة metadata حقيقية.
- اختبار AI عند بوابة الأدوات: استدعاءات أدوات وعدّادات آثارها الحقيقية، دون استدعاء نموذج AI أو مزوّد مدفوع.
- ثمانية طلبات HTTP متداخلة فقط لاختبار عزل التعديلات؛ هذه ليست محاكاة ضغط أو سباق عمليات متعددة/processes.
- حاضنة المشروع تثبت NODE_ENV=test وDATABASE_PATH=:memory: وتفرغ مفاتيح مزوّدي AI. حدود الطلبات في test أعلى من التشغيل؛ اختبار middleware يستنفد حد test، لا يقيس سعة الإنتاج.
- لم نصل إلى السيرفر المنشور بسبب قيود اتصال بيئة العمل. لم تُنشأ حسابات عليه ولم تُقرأ أو تُغيّر بياناته.

## الحالات الجديدة: نتائج مثبتة

| العائلة | ما جُرّب | النتيجة الفعلية |
|---|---|---|
| IDOR/BOLA | تغيير وحذف عنوان حساب B بجلسة وCSRF صحيحين لحساب A | 404، مع مطابقة سجل الضحية قبل/بعد |
| تزوير اختيار الحساب | account_id/accountId في query وx-account-id في header | قائمة عناوين A فقط |
| Mass assignment | إدخال id/owner/customerId للضحية عند إنشاء عنوان | سجل جديد ملك A، عنوان B لم يتغير |
| حقن في معرّف الكائن | صيغ SQL ونصوص تشبه اجتياز المسار و%00 | 400/404، لا توسيع للنتيجة ولا تعديل للضحية |
| SQL كنص | اسم يحتوي على صيغة DROP TABLE | خُزّن كنص حرفي في سجل المالك فقط، جدول الحسابات باقٍ |
| CSRF | غائب، مزوّر، من حساب ثانٍ، وقيم مدمجة | 403 INVALID_CSRF، سجل الحساب لم يتغير |
| إعادة استعمال الجلسة | منتهية، ملغاة، حساب BLOCKED/DELETED | رفض القراءة والتعديل بـ401 رغم معرفة CSRF الأصلي |
| Logout replay | استعمال Bearer بعد logout الفعلي | 401 للقراءة والكتابة |
| رموز دخول مزوّرة | رمز عشوائي، صيغة SQL، ورمز طويل | 401 دون data |
| خلط هويّتين | Cookie من B مع Bearer وCSRF من A | 403، لا تغيير لعنوان B |
| تزوير الامتيازات | role/isAdmin/status وحقول التحقق في تحديث profile | لم تُطبّق حقول الصلاحية والتحقق ولم يتغير حساب B |
| طلبات متداخلة | 8 محاولات تغيير/حذف لعنوان B | كلها 404، نفس سجل الضحية بعد اكتمالها |
| SSRF ملتوي | IPv4 رقمي/hex/octal/مختصر، IPv6 mapped، localhost مرمّز/unicode/trailing dot، metadata/private IP | رفض في محلل URL، بلا شبكة |
| DNS مختلط | hostname ظاهره عام يُرجع عنوانًا عامًا ومعه عنوان داخلي | رفض مجموعة العناوين كاملة |
| تلاعب بعرض سعر | تغيير كل حرف في payload/signature على حدة، واستبدال السعر بـ7 قيم | رفض كل التحويرات، مع قبول الرمز الأصلي كضابط إيجابي |
| تعليمات AI خبيثة | نص يدّعي الإدارة مع تهريب account_id/role/approved/system/authorization | TOOL_SCHEMA_INVALID؛ صفر تذاكر/تنبيهات ناتجة |

### توزيع الحالات الجديدة
- adversarial-customer-isolation.test.ts: عدد 25.
- adversarial-inputs.test.ts: عدد 27، وبعض الحالات تنفذ عدة تحويرات داخل الاختبار الواحد.
- assistant-tool-security.test.ts: أضيفت 5 إلى الحالات السابقة، فأصبح مجموع الملف 12.

تعليمات AI الخبيثة أعلاه لا تقيس مدى اقتناع نموذج لغوي بها؛ تثبت أن بوابة التنفيذ لا تمنح صلاحية لمجرد وجود هذه الحقول/التعليمات في السيناريو المختبر.

## اختبارات الحماية السابقة التي أُعيد تشغيلها
الجلسات وعدادات الإساءة، استرجاع كلمات المرور وOAuth handoff، إعدادات الحساب وpush، توقيع الأسعار، حجب الملفات الخاصة واجتياز المسارات، safeUrl وإعادة التوجيه/DNS pinning، bootstrap الإدارة، الأدوات المعلنة والممنوعة وidempotency، عزل التفاعلات والتفضيلات الاجتماعية، ورؤوس الأمان الأساسية.

الأمر القابل للإعادة من جذر المستودع:

```sh
npm run test:security:local
npm run typecheck
```

النتائج: 17 ملفًا / 198 اختبارًا ناجحًا؛ TypeScript ناجح؛ git diff --check ناجح. لم تتغير شيفرة التشغيل أو schema في هذه الجولة؛ أضيفت اختبارات وأمر تشغيل وتقرير فقط. البناء والتدقيق السابقان لا يُحسبان كبناء جديد ضمن هذه الجولة.

## حدود النتيجة وما لم يُختبر
- لا اختبار خارجي لـRender، TLS/CDN/proxy أو الأسرار الفعلية أو النسخ الاحتياطية.
- لا DDoS أو brute force كثيف أو قياس سعة؛ لا نعرف من هذه النتائج الحدّ الأقصى لتحمّل السيرفر.
- لا تغطية كاملة لكل endpoint ودور؛ CRUD العناوين ليست بديلًا عن كل موارد الطلبات والفواتير والإدارة.
- لا إثبات غياب XSS بكل شاشات العرض، ولا فحص ثنائي APK أو certificate pinning/rooting، ولا اختبار متصفح فعلي.
- لم تُجرّب رحلات دفع حقيقية أو خدمات مزوّدين مدفوعة.
- عدادات الذاكرة وحدود التسجيل وملكية push-token ودورة الربط بين الزائر والحساب ما زالت ضمن خطة مراجعة مستقلة. لم نعالج هذه الجوانب بالادّعاء أن 198 اختبارًا تكفي.

## الخطوة التالية
اختبار بيئة staging قابلة للوصول بعد تأكيد الهدف والبيانات والنسخ الاحتياطية، ثم مصفوفة صلاحيات لكل الموارد والأدوار، ومراجعة دورة push-device والروابط الخارجية بكل مستهلك. لا حاجة لشراء خدمات أو تغيير التخزين لمجرد تنفيذ الجولة الحالية.
