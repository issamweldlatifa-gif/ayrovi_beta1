# ZAYROVI Publication — Phase 1

**الحالة:** وثيقة التخطيط الأصلية. التنفيذ الفعلي ونتائج الاختبارات والحدود موثّقة في `zayrovi-publication-phase-1-delivery.md`؛ لا تُقرأ عقود المراحل المستقبلية أدناه على أنها منفّذة.
**التاريخ:** 2026-11-06

## 1. القرار والنطاق

تطوير `/publications` الموجودة، دون إنشاء مدخل Publication آخر أو تغيير Navigation أو أقسام Home/Stories/LENS/Reels. استبدال العرض القديم لا يعني حذف سجلات `publications`، تفاعلاتها أو روابط منتجاتها. يبقى زر «Découvrir» في À la une يصل إلى المسار نفسه.

Phase 1 = Publication Feed أبيض، Header ثابت، Categories، بحث منشورات، عرض تحريري متنوع، حالات تحميل/خطأ/فراغ وإعادة محاولة، قائمة افتراضية وتحميل صفحات. إعادة استعمال الربط الاجتماعي الموجود دون تقديم مزايا وهمية. Immersive Viewer وإيماءاته والشراء داخل المشاهدة والإعلانات والتوصيات خارج هذه المرحلة.

## 3. Wireframes وحالات الواجهة

### Feed

```text
Safe area
[← / ZAYROVI]       Publication       [Search] [Bell]
[For You] [Fashion] [Beauty] [Home & Decor] …
---------------------------------------------------
قناة رسمية                         [More مؤجل]
[              صورة تحريريّة كبيرة             ]
عنوان قصير
[Z-Heart + العدد] [Comments] [Share] [Save مؤجل]
[View products — فقط عند وجود روابط حقيقية]

منشور تالٍ بتنسيق مختلف تدعمه بياناته الفعلية
[             الصورة / النص                   ]
---------------------------------------------------
[تحميل الصفحة التالية / إعادة المحاولة / نهاية النتائج]
```

- الهوية: BrandMark الرسمي بحرف A دون عارضة، وليس كتابة شعار بديل بخط عادي.
- خلفية بيضاء لهذه التجربة؛ بنفس خطوط التطبيق، Safe Area، مقاسات الأزرار والهوامش من النظام الحالي. لا تغيير عالمي لثيم التطبيق.
- البنفسجي `#571EF6` للتصنيف النشط والتفاعل فقط، لا إطار بنفسجي حول كل منشور.
- تباين ووضوح نصي؛ أهداف لمس لا تقل عن 44 نقطة، أسماء VoiceOver/TalkBack، RTL/FR/AR، دعم تكبير النص.
- تنويع التكوين عبر قوالب تحريرية للصور/المنتجات/المقتطف، لا اختلاق Carousel أو Video. لا قص وجوه عشوائيًا لفرض اختلاف القوالب.
- البحث وتصنيف المحتوى حقيقيان، لا Chips تتغير بصريًا فقط.

### البحث

فتح البحث ضمن نفس Feed، حقل واضح مع إلغاء/مسح، debounce، مفاتيح Query مستقلة لكل تصنيف/بحث. لا عرض نتائج طلب قديم مكان طلب أحدث. العودة من حوار لا تعيد القائمة من بدايتها.

### حالات الشبكة

- أول تحميل: skeleton أو مؤشر واضح دون بيانات/أعداد مختلقة.
- أول خطأ: ErrorBlock + Retry.
- لا منشورات: EmptyBlock مختلف عن «لا نتائج لهذا البحث».
- خطأ صفحة لاحقة: إبقاء النتائج المحمّلة، Retry في آخر القائمة.
- Pull-to-refresh: نفس الفلاتر، لا مضاعفة السجلات.
- صورة تالفة: إطار بديل قابل للوصول؛ لا مساحة بيضاء صامتة.

### التفاعلات

- Like/Comment للزائر: تفسير الحاجة لحساب ومسار الدخول؛ لا إرسال طلب متوقع فشله وكأنه نجح.
- Like للمسجّل: حالة الخادم أولًا، تحديث متفائل مع rollback ورسالة عند الفشل، تعطيل الضغط المتكرر أثناء الطلب.
- Comments: Sheet قابل للإغلاق بزر Back وعلى Android، إعادة استخدام التعليقات الحقيقية. الردود لاحقة.
- Share: Native Share؛ دعم الويب بمشاركة/نسخ رابط متاح فعليًا، دون الادعاء بأن رابط Viewer الفردي موجود الآن.
- Save وMore: إن ظهرا في Phase 1 يكونان معطّلين بوضوح وشرح أنهما غير متاحين بعد، لا نجاح وهمي ولا تقرير لا يصل إلى أي مكان.
- الضغط على الوسائط لا يدّعي فتح Immersive Viewer قبل Phase 2. لا صفحة تفاصيل وهمية.

## 4. المكونات المقترحة

```text
app/publications.tsx               route + ErrorBoundary فقط
features/publications/
  PublicationFeedScreen.tsx        state + query orchestration
  PublicationHeader.tsx            BrandMark / Search / account notifications
  PublicationCategories.tsx        chips + accessibility
  PublicationCard.tsx              editorial rendering
  PublicationActions.tsx           real integrations / deferred states
  PublicationCommentsSheet.tsx     existing Comments integration
  publicationFeedLogic.ts          categories / mapping / ordering helpers
  PublicationReactionIcon.tsx      vector Z-Heart
api/publicationFeed.ts             parsing + bounded requests
```

قائمة FlatList واحدة قابلة للتمرير، لا FlatList غير قابلة للتمرير داخل ScrollView. `useInfiniteQuery` بمفاتيح تشمل category/search، إزالة التكرار بالـid، إلغاء الطلبات القديمة، `onEndReached` محمي. صور AppImage/cache الموجودة؛ لا تحميل فيديوهات أو تشغيلها تلقائيًا في Phase 1.

حالة التصنيف/البحث/offset محفوظة بمخزن feature محدود أو Query cache مع استرجاع موضع التصفح. لا إضافة Global Store غير لازم. عقود Viewer/Products اللاحقة تستقبل postId/mediaIndex، ولا تستبدل الـFeed.

## 5. عقود API المقترحة — غير منفّذة بعد

الحفاظ على `/social/publications` القديم لتجنّب كسر الويب أو المستهلكين الآخرين.

```http
GET /api/public/social/publication-feed?category=beauty&q=…&cursor=…&limit=12
```

```ts
{
  success: true,
  data: {
    items: [{
      id, title, subtitle, imageUrl, publishAt, channelId,
      category, kind: 'image' | 'product' | 'editorial',
      products: [] // روابط حقيقية منشورة وقابلة للبيع فقط
    }],
    nextCursor: string | null
  }
}
```

- Cursor ثابت بزوج `(publish_at,id)`، ترتيب تنازلي، حد أقصى 30، تصنيفات enum، استعلامات SQL parametrized، بحث محدود الطول، منشور `publie` وتاريخ مستحق فقط.
- لا نشر remark أو بيانات CRM الداخلية. Pagination لا تسحب كل السجلات ثم تقصها في الهاتف.
- الفئات: For You (فلتر عام دون فئة مخزنة)، Fashion، Beauty، Home & Decor، Lifestyle، Trends، Technology. لا تخمين الفئة من كلمات العنوان؛ العمود الجديد له قيمة تحريرية صريحة، والمحتوى القديم يُعرض في For You دون تصنيف مزعوم.
- تغييرات قاعدة البيانات إضافية فقط؛ لا حذف publications أو التفاعلات. CRM يحرّر الفئة من whitelist.
- حالة تفاعل المستخدم: توسيع مدروس أو endpoint قراءة مصادق عليه لدفعة IDs، مع `private/no-store` ومنع تسريب حالة مستخدم إلى مستخدم آخر. فصل الأعداد العامة عن الحالة الشخصية.
- كتابة Like الحالية toggle وليست idempotent: منع retry تلقائي قد يقلب الحالة مرتين؛ لا بناء ضمانات كاذبة فوقها.
- Save/replies/report/contracts Ads لا تُنشأ صوريًا في هذه المرحلة.

## 6. هوية ZAYROVI للتفاعلات والوسائط

- Z-Heart: قلب هندسي بحافتين ناعمتين وشق/لمعة Z دقيقة؛ outline غير نشط وfill بنفسجي عند الإعجاب. الاسم المقروء يظل «أعجبني/إلغاء الإعجاب» لا اسم غامض.
- Emoji خاص = sticker/رمز رسومي داخل التطبيق، وليس Emoji Unicode جديدًا. ننفّذ رسومات SVG قابلة للتحجيم، لا PNG صغيرًا لأزرار حساسة.
- لوحة تصوّر AI للواجهة للمراجعة: ليست لقطة تطبيق منفّذ. اعتمادها لا يعني وجود فيديو أو backend وراء الأزرار المرسومة.
- صور المنشورات الفعلية لا تُستبدل بصور مولّدة دون قرار نشر واضح، ولا تُضاف تفاعلات/أعداد وهمية. أصول الحالات الفارغة يمكن توليدها دون اختلاق محتوى تجاري.
- لا توجد أداة توليد فيديو فعلي في الجلسة. لا إنشاء MP4 صوري أو تسمية slideshow فيديو مولّد. تجهيز عقود الوسائط يأتي مع مرحلة تدعمها فعلًا.

## 7. الاختبارات وبوابة التسليم

### Phase 1

1. À la une وأي مدخل قائم يفتحان `/publications` نفسه.
2. لا تعديل لعدد/ترتيب tabs أو صفحات Stories/Reels.
3. منشورات CRM المنشورة فقط، مع تصنيف وبحث فعليين.
4. Pagination مستقرة عند تساوي التواريخ، دون سجلات مكررة أو تسريب مسودات.
5. الرجوع من Comments/بحث/منتج يحافظ على حالة Feed؛ إعادة الدخول بحالة محفوظة وفق السياسة الموثقة.
6. Like/Comment لا يكذبان بشأن الحساب أو الاستمرار؛ الخطأ يعيد الحالة السابقة.
7. الحالات الأولية والفراغ والخطأ وخطأ الصفحة التالية وصورة تالفة.
8. عدم تحميل كامل السجل أو nesting VirtualizedList في ScrollView.
9. العربية/RTL وFR، Safe Area، وصول وأهداف لمس.
10. TypeScript والبناء واختبارات المنطق/UI وChromium؛ اختبار Android/iOS حقيقي يبقى منفصلًا عن Expo Web.

### مؤجل صراحة

اختبارات Swipe بين الصور/المنشورات، Viewer أسود كامل، تشغيل/إيقاف فيديو، Reply threads، Saved Collections، Hotspots، Add to Cart داخل Viewer، Sponsored analytics والتوصيات الذكية لا تُعد ناجحة في Phase 1 لأنها لم تُنفّذ فيها.

## 8. تسلسل التنفيذ

1. اعتماد الاتجاه البصري للـFeed وZ-Heart.
2. تغييرات API/DB/CRM الإضافية + اختبارات العقد والخصوصية.
3. مكونات Feed وكتابة التفاعلات الموجودة + حالات الشبكة والحالة المحفوظة.
4. التحقق البصري على المسار الفعلي، اختبارات، توثيق الفوارق، ثم الدفع.
5. Phase 2 وما بعدها بعقود مستقلة. لا إعادة كتابة Feed عند إضافة Viewer.
